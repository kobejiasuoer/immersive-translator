## 0. 执行摘要

**总体评分：2.9 / 5。** 单点功能工程质量高（测试 379 绿、错误分类成熟、数据层原子写），但产品作为「一个用户明天愿意再打开的东西」尚未成立：激活与回访两条链在第一环就断，学习闭环的「读→查→存→复习」四环已通、「练/用」两环没接。

**一个改变所有结论的工程事实**：【事实】R1–R4 四个需求（docx/pdf 导入、学词笔记、口语陪练、录音直译）加上影子跟读评测与云 TTS，**已全部在工作区实现且 vitest 379 passed（2026-09-15 实测），但未 commit、未发布**（`git status`：`speak_store.rs`、`fileImport.ts`、`SpeakView.tsx`、`livecaption/`、`VocabNoteDialog.tsx` 等全部 untracked）。种子用户测的是没有这些功能的 v0.5.2——她反馈的最大痛点（Word/PDF 导入）已经写完了。**当前最重要的动作不是规划新功能，是发布这批代码并让种子用户复测。**

**最致命的 3 个问题**
1. **「装了像没装」**（A1/A2/D1）：启动后无任何窗口（`tauri.conf.json` 8 窗全 `visible:false`）、托盘左键无任何行为（`lib.rs` 无 `on_tray_icon_event`）、无开机自启（全仓 grep 零命中）——新用户装完唯一可见物是一个右键才有反应的托盘图标；提醒/角标回访链在重启后整条死亡。
2. **闭环只差最后一公里没接线**（C1/C3/C4）：生词 → 口语陪练零通路（`speakLogic.ts:8` 明示不经过 SRS）、口语产出（跟读低分词）不回流生词本、翻译历史与生词/阅读室零引用（`history.rs:35-52`）、录音转写只能存文件。数据枢纽（生词本）两头都断在「练」和「用」。
3. **回访钩子全部压在「生词本有词」这个未发生的前提上**（D1/D3）：SRS 到期队列、托盘角标、每日提醒、快速复习窗四个回访机制的数据源全部是 `reader_vocab.json`，而种子用户原话「生词本我还没用」——回访引擎造好了，油箱是空的。

**最重要的 3 个建议**
1. **两周内发 0.6.0**：提交并发布 R1–R4 + 语音 wave，同车带上 P0 修复（首启引导窗、托盘左键弹菜单、开机自启开关、快速复习旧数据 bug、TTS 静默失败提示），立刻让种子用户复测。
2. **把「生词」确立为全产品唯一数据枢纽**：所有功能只做一件事——向生词本输入（浮窗、阅读、口语跟读低分词、历史、转写），笔记与复习是它的两个出口。本期只加 3 个串联点（S1 口语结束沉淀生词、S3 历史条目→生词/阅读室、S4 读完结课动作），不加任何全景跳转按钮。
3. **结束盲飞**：落地本地 JSONL 埋点（15 个事件，零出网）+ 北极星「周有效学习会话数」，两周后用它回答「种子用户之外的第二个人会从哪来、断在哪」。

### 1.3 新用户 10 分钟测试（代码走查推演）

前提事实：【事实】安装启动后**没有任何窗口出现**（8 窗全 `visible:false`，`lib.rs` setup 无 show 调用）；托盘 tooltip 是「ImmersiveTranslator」；**左键点击托盘图标无任何反应**（`lib.rs:1148-1177` 的 builder 链无 `on_tray_icon_event`，全仓 grep 零命中）。

| 2 | 左键点托盘 | **毫无反应**（A1） | — |

| 4 | 按不出任何热键（无人告知 Ctrl+Shift+Q） | 空转 | **低** |

**结论**：【推断】主线「划词翻译 → 阅读室 → 生词本」在无文档情况下自然走通的概率很低，卡点按顺序是：托盘左键死键（第 2 步）、热键无人告知（第 4 步）、引导藏在设置里（第 6 步）、「生」按钮语义不明（第 9 步）。各功能新用户发现概率：翻译历史/截图 OCR **高**（托盘可见+中文可猜）；划词翻译 **中**（托盘右键后可推知有热键）；阅读室 **中低**（名字不透明但空态文案好）；生词本复习 **低**；口语陪练 **低**（藏最深）；录音直译 **中低**；学习提醒 **低**（首次弹出前完全不可见）。

### 1.4 窗口爆炸评估

【事实】预建 8 窗：panel、settings、history、reader、ocr-overlay、reminder、live-caption、quick-review（`tauri.conf.json:14-127`），全部启动时创建、各自独立 WebView 实例。【推断】其中 overlay/reminder 是瞬时窗（存在合理）；quick-review 是回访触点（合理）；真正撑不住的是 **history 独占一个常驻窗口**——它承载的是低频「找回刚才的翻译」，同级别功能（生词本）都选择寄居阅读室。但窗口数量不是当前主要矛盾（见 B10 性能），**砍窗口的收益小于把窗口接进闭环的收益**，建议 history 维持现状、P2 再评估降级为阅读室一个 tab。

### 2.1 跨功能一致性总评

【事实】**「多套 CSS 分裂」的假设不成立**：`reader.css`（3743 行）头注释明示「令牌全部来自 styles.css」，styles.css 含四主题令牌（`styles.css:1956-2035`）；quickreview/reminder/liveCaption 三套 css 也声明消费全局令牌。真正的分裂是**行为层**：主题应用（B3/B4）、窗口关闭语义（B5）、收藏语义（A5）、原子写（B6）。视觉是同一套设计系统，交互预期没有统一。

### 2.2 心智模型

三种形态（浮窗用完即走 / 阅读室驻留 / 卫星窗瞬时）各自内部自洽，且历史决策（阅读室是延伸空间、浮窗快轻不打断）在代码里得到遵守：浮窗失焦 400ms 自动隐藏+固定豁免（`TranslationPanel.tsx:1050-1068`），阅读室独立窗口不抢浮窗交互。**不自洽的一处**：「什么时候该弹独立窗」规则漂移——快速复习（SRS 触点）有独立窗，而同属触点的口语陪练藏在阅读室二层、录音直译又是独立窗。判断标准应该是一条：**「用户主任务之外的轻任务→卫星窗；需要内容上下文的任务→阅读室内」**。按此标准口语陪练进阅读室是对的（依赖文章/生词语境），录音直译独立是对的（独立场景），快速复习独立也对——现行归属大体合理，缺的是入口可见性（A3/A4），不是形态错误。

### 2.3 状态完整性

逐功能空/加载/错误/权限四态走查结论：翻译浮窗（六态状态机+骨架屏+分阶段文案，`TranslationPanel.tsx:84,171-183,1277-1281`）与语音三件套是模范生；缺口集中在 B2（朗读静默失败）、OcrOverlay 失败无自动重试按钮（`OcrOverlay.tsx:134-141`，P2）、以及所有窗口共有的 B8（无 ErrorBoundary）。

### 3.4 反串联检查（明确不做的）

判断标准：**数据上无下游价值 / 时机上打断主任务 / 形态上属于另一个心智空间**。

1. **阅读室 → 浮窗查词**：不做。阅读室有固定词典栏（`DictColumn`），把用户拽回浮窗是开倒车（两个心智空间）。
2. **历史/转写自动生成生词**（无用户动作）：不做。翻译≠学习，没有「我想记住它」的意图信号，自动沉淀会瞬间污染生词本——生词本的价值恰恰在于稀疏。
3. **口语陪练中途弹复习提醒**：不做。`review_reminder.rs` 调度只看时钟不看前台窗口（`review_reminder.rs:259-274`），提醒卡是全局置顶——建议 P1 给调度加「阅读室 speak/review 视图活跃时顺延 30 分钟」的抑制位，避免打断主任务。
4. **快速复习窗塞听写卡**：维持 decisions #14 的裁剪（无 TTS 连播语境），不要为了「功能全」加回去。
5. **录音直译自动进生词/自动存历史**：不做自动，只在用户主动保存时给 S4 式的一键选项（用户对录音内容有无学习意图，只有他自己知道）。

## 4. 模块 D · 留存与增长诊断

### 4.1 回访理由盘点

| 机制 | 钩子强度（设计） | 钩子强度（实际） | 证据与断点 |
|---|---|---|---|
| 每日复习提醒卡 | strong | **weak→medium** | 设计好（置顶不抢焦点、双按钮、免打扰、每天一次，`review_reminder.rs:53-78`）；但前提是 app 在运行——无自启（A2）使重启后链条全断【推断】 |
| SRS 到期队列 + 托盘角标 | strong | weak（当前） | 机制扎实（`due_count` 30s 刷新，`reader_store.rs:541-555`）；但数据源是生词本，种子用户还没用（D3） |
| 快速复习迷你窗 | medium | medium | 「收起不丢进度+每卡即评即落盘」是好设计（decisions #14）；有 B1 旧数据 bug |
| streak 连续打卡 | weak | weak | 有展示（`readerSrs.ts:109-159`）无强化（无周报/里程碑/补打卡） |
| 内置文库「今日一篇」 | weak | weak | 按日期轮换（`library.ts:33,44-46`）但没有任何触达渠道告诉用户今天换了 |
| 口语「上次的对话」 | weak | weak | 可续（`SpeakView.tsx:481-496`），但无练习计划/课程感 |

**回答「今天用完，明天为什么再打开」**：当前唯一可靠的答案是「昨天攒了生词、今天有到期」（SRS 闭环）。它对已经形成习惯的用户是 strong，但把 100% 的赌注押在「生词本已被用起来」上——而激活链（D2）恰恰没有保障这一点。

### 4.2 激活漏斗

安装 → ①发现托盘（左键死键）→ ②学会热键（无人告知）→ ③配置 LLM Key（BYOK 硬门槛，`Settings.tsx:362-538`）→ ④第一次翻译 → ⑤打开阅读室 → ⑥导入内容（内置文库可跳过此步）→ ⑦第一次收藏生词 → ⑧第一次复习。**8 步，3 个硬门槛**（①②合并的发现门槛、③的 BYOK 门槛、⑦的「生」按钮语义门槛）。【推断】每步保守流失 50% 的话，到 ⑧ 所剩 <1%。

压缩方案（对应路线图 P0）：首启引导窗把 ①②③ 压成一步（三卡片：热键表+配 Key 按钮+「用内置文章试试阅读室」）；内置文库作为零门槛首读内容（⑥→0 步）；S5 把 ⑦⑧ 接起来。

### 4.3 用户画像对齐

【事实】现有功能集合实际服务的主线画像与种子用户完全重合：**「手头有英文 Word/PDF/网页材料、要读懂、顺手学词、排斥背单词形态、想要口语输出」的成人自学 者**。次要功能群（术语表=职场翻译、OCR/录音直译=内容搬运/会议场景）服务的是**未被任何用户证据支持的画像**。【推断】这一个人代表的市场不大，但「用真实材料学英语」的人群（考研/四六级/雅思备考 + 职场进阶阅读）是可观的利基，且竞品在此没有强势桌面玩家（见 4.4）。**建议收窄**：定位语收敛为「把你自己的英文材料，变成你的词汇量和口语」，术语表与录音直译降级为「不投入、不顺路不删」，OCR 明确不加资源（与 R1-R4 战略取舍一致）。考试词表保持「导入时的覆盖提示」这一附属形态（`ImportDialog.tsx:227-237,285-298`），**不要**滑向考试产品（用户排斥背单词形态的信号同样适用于「刷词表」）。

### 4.4 竞品生态位

| 竞品 | 它强在哪 | 它缺什么（=我们的位置） |
|---|---|---|
| 有道/欧路词典 | 词典权威、屏幕取词成熟 | 「你自己的材料→结构化生词→产出式复习→口语评分」的整链；欧路有学习功能但依赖内置书城而非用户自己的 Word/PDF 工作流 |
| 沉浸式翻译浏览器插件（同名不同产品） | 网页沉浸翻译体验、2000 万用户 | 无生词本/复习/口语（`mobile-app-research.md §2` 已论证不正面竞争）；但它教育了用户「沉浸式翻译」这个词，是命名风险也是流量词 |
| Language Reactor / Linguist | 视频/网页双语字幕+逐句 | 桌面本地文件（Word/PDF）场景零覆盖；无发音评测 |
| Bob/Pot/沙拉查词 | 划词工具轻快 | 纯工具无学习闭环 |
| 豆包/系统 AI | 免费、大厂、全能 | 通用助手无学习状态（无 SRS/无进度/无生词资产）；用户已点名它让截图翻译失去差异化 |
| 背单词类（墨墨/不背） | SRS+提醒+小组件留存标杆 | 无「从我的阅读中来」的内容源（`mobile-app-research.md §3`）；恰是用户排斥的形态 |

**唯一不可替代的组合**：【推断】「用户自己的英文材料（Word/PDF/网页/划词）→ 查词即沉淀为带语境的生词（含搭配与直译陷阱数据，`chunkAnnotate.ts` 独有）→ 产出式复习（完形/听写/直译陷阱反馈）→ 一键成笔记 → 发音评测与口语陪练」——每一环单看都有人做，**整链在同一桌面工具里、以用户自己的材料为源头，没有对标产品**。伪差异化：截图 OCR（用户点名，`user-feedback §5`）、录音直译（会议翻译场景大厂全有）。

### 4.5 北极星与最小埋点（详见 §6）

零埋点已验证【事实】（全仓 grep telemetry/analytics/sendBeacon 零命中；唯一出网是 Google Fonts 字体请求，`ReaderApp.tsx:806-815`、`QuickReviewApp.tsx:63`，且 CSP 为 null）。北极星建议：**周有效学习会话数**，「有效学习会话」= 满足其一：阅读室单次会话 ≥5 分钟且含 ≥1 次查词/收藏/跟读；或完成 ≥5 张复习评分；或口语完成 ≥3 轮对话。浮窗纯翻译不计入（它是获客工具，不是留存理由）。

### 4.6 可持续性（成本）

【事实】模式是用户自带 LLM Key + 讯飞免费额度（ISE 90 天 1 万次、在线 TTS 每日 500 次，`voice-roadmap.md §0/§1.1`），**成本完全由用户承担**，验证期不烧钱——这是这个产品能慢慢打磨的前提。【推断】规模后的天花板不在 LLM（BYOK 可扩）而在讯飞 ISE：90 天 1 万次评测对重度跟读用户约 3 个月耗尽，之后 0.6 分/次的价格对个人用户偏贵；`voice-roadmap.md §2.1` 的 Azure PA（5 音频小时/月免费）是必要的第二供应商。**现阶段建议**：不做任何平台补贴；在设置抽屉评测凭据区展示剩余配额感知（次数计数即可），避免用户「突然没声」时归咎产品；多供应商抽容按 voice-roadmap 排期走。

### 4.7 反馈渠道

【事实】目前靠微信单点（`user-feedback` 文档即产物）。最低成本闭环建议（按优先级）：①设置「关于」区加「反馈问题」按钮=mailto: 深链 + 自动附脱敏诊断文本（`errorMessageFormatter.ts:410-434` 已有诊断报告生成器，复用即可，半天工作量）；②每次发布用托盘 tooltip/更新弹窗带一句「这版新增了什么」（updater 已有手动检查入口，`Settings.tsx:785-817`）；③暂不建社群（1 个用户撑不起运营），种子用户的微信通道保持高频人工——**10 个用户以内，人工是最好的反馈系统**。

| 考试词表 | **收缩为附属** | 导入提示位已足够；严禁滑向刷词表产品 |
| 口语陪练（R3） | **加深** | 最强用户诉求（唯一被重复表达）；当前是能跑的 MVP，缺与生词的连接（S1）与练习感 |
| 录音直译/实时字幕（R4） | **维持观察** | 单用户兴趣驱动；与学习主线距离最远；做完 S4 式「保存时可选进阅读室」后停止投入，看使用数据 |
| 影子跟读/发音评测 | **维持（中期再加深）** | 链路完整、错误态好；加深方向在 voice-roadmap（人话讲解）而非本报告排期 |

### 5.2 三选一思想实验

**保留：① 阅读室 ② 生词本+复习（含学词笔记）③ 口语陪练。**

理由：这是「读→存→复习→用」闭环的四个物理承载（①②③ + 笔记挂在②下）。砍掉浮窗？不行——它是获客口和阅读室的内容进水口；但如果题目是「打磨到极致」的取舍，浮窗的核心交互已经成型不需要「打磨资源」，而这三个功能离「用户明天再打开的理由」最近，且恰是竞品组合拳里没有的部分。砍掉的其余功能全部保留代码、隐藏或维持现状（见 5.4）。

### 5.3 「深」的验收标准（可验收，拒绝话术）

| 功能 | 「深」的定义（全部可从埋点/代码验证） |
|---|---|
| 阅读室 | 用户单次会话 ≥20 分钟（会话=打开阅读室到 hide），期间 ≥3 次查词或 ≥1 次生词收藏，且读完 ≥1 篇（进度 ≥90%）；周复购 ≥2 次 |
| 生词本+复习 | 生词周净增 ≥10（入账-删除）；到期复习完成率 ≥60%（复习数/到期数）；学词笔记月导出 ≥2 次 |
| 口语陪练 | 周主动开新会话 ≥3 次（排除从书架误入：会话 ≥3 轮才算）；单会话 ≥5 轮；跟读打分使用率 ≥50%（打过分的轮/总轮） |
| （护栏）生词→口语连接（S1） | S1 上线后：口语会话产生的生词占周新增 ≥20%，证明连接有效 |

### 5.4 砍掉的处理方式

本期没有「彻底移除」级结论（见 5.1），全部收缩项采取**隐藏入口不减代码**：OCR/术语表/录音直译保留托盘或设置内入口，数据（history.json、speak sessions）原地保留不迁移（schema 已有 version 字段，未来真移除时做 v2 迁移）。唯一建议的破坏性动作是 P2 评估把 history 窗口并入阅读室（1.4），届时数据文件不动、仅 UI 迁移。

## 9. 假设与风险（没把握的都在这里）

1. **单样本风险（最高优先）**：全部需求验证来自 1 位种子用户。R3 口语陪练的「最强诉求」、R4 的兴趣、S1/S3/S4 串联点的价值、5.3 的深度标准数值，全部是【猜测】，需 0.6.0 发布后她的复测 + 第二个用户验证。本报告的画像判断（4.3）与市场大小推断尤其脆弱。
2. **性能未实测**：B10/A9 的启动时间、8 窗内存、长文翻译耗时全部是读码推断（标注处已写）。P2-4 动手前必须先量化，避免优化不存在的瓶颈。
3. **未覆盖范围**：macOS 端（`immersive-translator-mac/`）未审计；`src/reader/ReviewView.tsx` 等 UI 的实际渲染效果未运行 GUI 走查（全部结论来自代码走查与测试，未做真机交互验证）；e2e 测试 5 个 skip 按既有约定跳过，未核实其历史原因。
4. **未提交代码的成熟度**：R1–R4 仅过了 vitest（379 绿），未过真机验收流程的完整证据未核实（需求卡要求 `pnpm tauri dev` 真机走查，工作区无对应自检报告）。P0-1 发布前建议按需求卡逐条真机验收。
5. **竞品判断时效**：4.4 基于仓库内调研文档（`mobile-app-research.md` 2026-09、`voice-roadmap.md` 2026-09-15）与用户原话，未做当日新调研；「无对标产品」的结论随大厂发布节奏可能快速失效。
6. **ISE 配额数字**沿用 voice-roadmap 的调研（90 天 1 万次），未向讯飞控制台核实当前账户实际额度。
7. **P0-4 自启插件的兼容性**（Windows 11 22H2+ 的启动应用通知）未验证；默认关闭是保守选择。
8. **报价类结论的口径**：激活漏斗「每步 50% 流失」是说明结构风险的修辞，不是测量值。
