## 决策

### 1. 存量讯飞用户登录沉浸云后 → 自动切云

原定稿倾向「只引导不代切」。**决策:登录完成的瞬间自动把 `voiceProvider` 写为 `gateway`**,讯飞凭据原样保留、随时可切回。

- 实现要点:登录成功回调里更新设置并立即刷新消费点路由;自动切换对用户可见(语音页卡片选中态变化 + 一条轻提示,如「已切换为沉浸云语音」),不做静默代切。
- 未登录的存量讯飞用户维持原迁移推断(任一讯飞凭据存在 → 默认 `xfyun`)。
- 原型无需改动,实施时按此行为。

### 2. 阅读室 `ttsProvider` 枚举语义升格 → 独立立项

确认单独立项。项目 prompt 已备好:`docs/reader-tts-provider-upgrade-prompt-2026-10-28.md`。

### 3. 配额实时余量由 `me/config` 下发,客户端常驻显示

**决策:是。** 服务端在 `me/config` 的 `voice` 段补配额字段(建议含 asr/tts/ise 各自余量与 `resetsAt`);客户端语音页从「402 事件式展示」升级为**常驻实时余量条**,402/`x-quota-*` 头仍作兜底校验。

- 字段未上线前,客户端按原定稿的 402 事件式方案兜底,字段上线后切换为常驻显示。
- 服务端字段设计需与 `quota.service.ts` 的 UTC 自然月周期一致(文案统一「本月额度」)。

### 4. 一键测试真实语音样本

**决策:确认。** 云 TTS 生成一句固定英文,产物以 32-64KB PCM 常量打包进客户端;接受每次测试消耗 1 次评分额度。

### 5. 账号页兑换码入口 → 开发

**决策:确认开发,与语音网关接入同批落地。** 服务端 `POST /v1/redeem` 已存在;客户端需在账号页新增兑换码 UI(输入 + 错误文案映射 `REDEEM_CODE_NOT_FOUND/EXPIRED/USED`)。语音页「兑换更多额度」按钮直接指向该入口——此前「先跳账号页占位」的降级方案作废。

### 6. `voiceProvider` 不纳入云同步;口语数据纳入

**决策:分两半。**

- `voiceProvider` 等 AppSettings 本地偏好:**不纳入云同步**(与 LLM provider 选择同口径)。
- **口语对话记录、跟读评测记录等信息:需要纳入云同步**——新增范围,原定稿未覆盖。涉及服务端同步端点设计、记录归属(账号)、多端冲突策略(建议最后写入胜出 + 按 timestamp 合并),建议单独立项,排期在语音网关接入之后。

### 切分记录(2026-10-28 终审补记):主批次不接 TTS 消费点

语音网关主批次**有意不接任何 TTS 消费点**:阅读室朗读完全走存量 `readerTypes.ttsProvider`(硬契约 8:阅读室 TTS 支线零回归),选沉浸云后的「云端朗读」当前唯一消费点是语音页一键测试。`voiceRoute.EDGE_FALLBACK_NOTICE`(「已临时使用 Edge 朗读」)是契约 §三.5 的回落标注,为阅读室 TTS 支线(上面决策 2 的独立立项)预留——该批次在 speechEngine 引擎分发处挂 `resolveVoiceRoute("tts")` 守卫并消费此标注,主批次未消费属切分而非漏接。
