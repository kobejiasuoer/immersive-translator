# 更新后阅读记录不可见排查

## 结论与现场证据

用户反馈更新后阅读室书籍、生词和阅读进度消失，并询问是否必须登录才保存。

- 未登录也会持久化学习记录。主存储为 `%APPDATA%/com.immersivetranslator.windows/learning.sqlite3`；旧 JSON/Markdown 文件仍可作为兼容读取来源。
- 游客和账号拥有独立学习空间。游客使用应用数据根目录，账号使用 `learning/account-<用户 ID 的十六进制>`。登录时 `adopt_guest` 在事务内将游客资料领入该账号，并将原游客快照标为空；退出后不会在游客空间展示原账号的记录。
- 本机只读 SQLite 核对发现两个账号空间仍有资料：分别为 1 本书 / 5 个生词 / 41 条会话，以及 4 本书 / 13 个生词 / 8 条会话。两者均有非零阅读进度。游客的 12 个文件快照全部为 NULL，符合已经领入账号后的状态。
- 本机当前安装运行版本为 0.15.2。仅检查 `secrets.json` 的键是否存在，确认没有 `server_auth` 槽；未解密凭据。已安装应用的可访问界面显示空书架、零短文、零待复习。当前无保存的登录凭据与空游客空间可以解释这次不可见现象，但没有足够证据判定凭据为何消失。
- 应用 identifier 不随版本或安装目录改变。应用内 NSIS 更新传 `/UPDATE`，安装模板在更新模式直接覆盖；只有手动卸载且勾选删除应用数据才清数据。自定义钩子只处理 DirectML DLL。本次没有更新清除本地资料的证据。

恢复现有资料的路径是重新登录原来的同一账号。账号不同会进入不同空间；不能通过合并所有账号库来绕过隔离。

## 确认并修复的独立启动缺陷

`auth_bootstrap` 从磁盘恢复登录后，原先直接发布 `auth-state-changed`，没有先设置学习空间。前端收到事件会立刻读取列表；如果事件早于 `auth_get_status`，读取的仍是默认游客空间。后续身份相同的事件可能不再触发重读。

`auth.rs` 现在在唯一的身份事件发布入口先调用 `learning_store::set_account`，再广播事件。覆盖启动预填、刷新成功、致命失效和显式退出；删除登录、退出两处重复的空间设置。游客领入规则、账号隔离、存储路径和安装行为均未改变。

该修改只保证身份事件发布前选中相应学习空间，不是对登录凭据消失原因的修复。现有 `auth_get_status` 的身份快照与空间设置之间仍可能被并发身份变化抢占；首次引入账号隔离的旧版资料领入也未扩展处理。
