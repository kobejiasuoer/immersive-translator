# Windows 主题与图标统一实施记录

日期：2026-10-30。

依据：已确认的半保真交互原型，以及 [调整计划](./windows-theme-icon-unification-plan-2026-10-30.md)。用户明确保留既有主题范围：阅读室可手动选择主题，设置等窗口跟随系统；快速复习沿用原有阅读偏好来源。

## 实施内容

- 统一公共品牌为墨绿，浅色 `#1f6b57`，深色 `#73c6aa`。公共 `--accent-*` 在每个显式主题根节点重新派生，补齐填充前景、按压、高亮、阴影、焦点和选区，避免系统与阅读主题相反时串色。
- 设置、历史、翻译等工具页使用中性浅底；阅读纸面与阅读字体保留，护眼继续灰绿，OLED 使用独立纯黑背景。设置仍跟随系统，未增加全局主题状态或保存字段。
- 阅读室四视图使用相同的平面顶栏与绿色选中态，主操作按钮收敛为 8px 圆角；保留 folio 对正文、侧栏与播放条的布局作用域。
- 顶栏由循环主题按钮改为带色样的主题按钮与选择面板，可直接选择纸书、深色、护眼、纯黑，仍只发送已有 `{ theme }` 回调。抽屉的色样、名称与选中状态对应实际主题。
- 阅读快捷键对 `HTMLSelectElement` 不生效，保证主题下拉框的空格等原生键盘操作不会误触朗读。翻译、播放、评分、同步及设置保存业务未修改。
- 填充品牌色的按钮、标记、开关使用主题配套前景；真实录音继续使用错误/录音红色。服务商识别色、句法与笔记内容标注保留自己的语义。
- 引导、提醒、快速复习、录音直译、OCR 尺寸标签和错误兜底的旧品牌色同步调整。错误兜底保留内联样式和 CSS 变量缺失时的浅色回退值。
- APP 图标最终采用用户选定的 B「书页对话」，以浅绿左书页、白色右书页及对话尾角表达从阅读进入口语。正式 SVG 母版同步生成 18 个桌面图标和官网同源 PNG。
- 官网导航为绿色图标增加 38px 浅色承托，内图仍为 30px，在深绿首屏和浅色导航中均有明确轮廓。详见 [官网品牌图标检查](./website-brand-icon-2026-10-30.md)。

## 资源生成

正式母版：`immersive-translator-windows/src-tauri/app-icon.svg`。

在 Windows 工程下运行 `python scripts/make-icon.py`，使用已安装的 Tauri CLI；先临时生成和校验，成功后按白名单逐文件替换。旧箭头生成器及删除 Square/Store 资源的逻辑已经移除。ICNS 图像块排序固定，重复生成不会因容器顺序产生无内容变化的差异。

实际验证：16 个 PNG 解码、尺寸及透明四角，ICO 的 16/24/32/48/64/256px，ICNS 解码，MSIX 五个资源齐全；重复生成 19 个同步文件的哈希不变，模拟 CLI 失败时正式资源哈希不变。官网与正式 512px PNG 使用相同字节。

## B 图标定稿与主题面板优化

用户选择 B「书页对话」后，正式资源与候选图像逐字节一致，18 个桌面资源和官网图同步生成；官网仍采用 38px 浅色承托，内图 30px，桌面/手机与浅深导航的定向展示检查通过。dev 自动重建的新 EXE 已提取确认 B 图标。

随后根据用户反馈，将 Windows 原生下拉菜单改为 224px 的主题面板，提供实际纸面色样、说明、选中标记及统一控件样式。支持鼠标、方向键、Home/End、Enter/Space、Escape、Tab 与外部关闭；选择仍沿用原设置回调。

修复两个交互边界：主题控件放行 H/h 的 keyup，保证正文按住揭示后仍可释放清理；窄窗解析栏以顶栏下方的 `.reader-body` 为定位边界，防止覆盖闭合主题按钮。菜单展开时顶栏仅提升到 31 层，保持高于 30 层透镜、低于其他浮窗。播放 dock、译文浮层和 ViewMenu 的原定位边界保留。

最新 19 项主题控件定向测试通过；43 项真实浏览器检查覆盖 1200/960px 四主题、闭合与展开命中、透镜模式可点击、620px 短窗、鼠标与键盘选择、Escape、Tab、外部关闭及 Runtime。最终类型检查、CSS 解析、Vite 与 Windows 原生构建通过。已重新生成本地 MSIX，核对包内最终 EXE 与五项 B 图标资源一致；未部署官网或发布应用。

复测过程中一次并行 Node 检查遇到本机内存分配失败。改为串行、限制检查进程堆大小后，TypeScript、主题选择测试及 Vite 构建实际复测通过；未因此调整生产代码或依赖。

浏览器检查和截图位于本机 `.taste-skill/theme-unification/`，不是 Windows 原生端实拍，不使用私人学习资料或真实录音，也不接通账号、模型、语音或同步服务。

## Dev 图标构建跟踪修正

用户重启 dev 后，前端已加载新主题选择器，但标题栏仍显示紫色图标。实际进程启动于 17:16，debug EXE 却仍是当天 10:26 的旧文件；图标资源于 16:20 更新，release EXE 已是新图标。

锁定的 Tauri 2.6.3 构建辅助默认没有把原始图标加入 Cargo 重建依赖；宏实际跟踪的是 OUT_DIR 中转换后的图标缓存。仅刷新前端或重启 dev 会复用旧 debug EXE。

在 `src-tauri/build.rs` 显式增加 `cargo:rerun-if-changed=icons`，现有 tauri dev 监控随后自动完成重新构建。新 debug EXE 写入时间为 17:28，重启进程来自同一路径；从新 debug EXE 提取图标确认已经变为墨绿 A/文。新增构建输出也确认追踪了 icons。没有执行 cargo clean、清除 Windows 图标缓存或修改业务逻辑。
