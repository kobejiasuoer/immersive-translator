# 官网移动端章节交接

日期：2026-11-04。

## 用户意图与工作边界

本轮官网提供 Windows 与 macOS 的明确下载入口。移动端作为独立 `#mobile` 区域保留，由用户随后交给 Mac 上的 AI，根据实际移动端工程、真机情况与发布渠道自行补全。本交接文件不发送消息、不创建新聊天、不触发移动端发布。

当前默认状态为**开发中**。未完成验收前，不把原型或开发预览标作正式移动端截图，不提供虚构下载地址，不宣称原声录音跨设备同步。

## 接手时需要确认

1. 先读仓库 `AGENTS.md` 与移动端工程和最近执行记录，确认已实现、开发中、计划中的功能分别是什么。
2. 使用真实移动端应用画面替换预览，记录设备、系统版本、应用版本、截图日期及素材来源。截图不得包含私人学习资料、账号标识或真实令牌。
3. 说明发布状态：开发中、受邀测试或公开可用。只有核实可访问渠道后才添加 App Store、TestFlight 或其他真实安装链接；测试邀请不得冒充公开下载。
4. 逐项核对阅读、练习、生词复习、同步等功能范围。Windows、macOS 与移动端分别演进，不能仅因客户端名称一致就宣称功能完全相同。
5. 同步文案按实际实现确认：步骤、草稿、文本回答、反馈、原文定位、复习记录等需分别核查；原声文件若只在录制设备保存，明确说明这一范围。
6. 对新增安装渠道和功能主张给出验证证据，更新本文件的验收记录。

## 官网接入约定

- 移动端内容位于 `website/upgrade.html` 的 `<!-- mobile-section:start -->` 与 `<!-- mobile-section:end -->` 之间，替换这一区域即可，不改变 Windows/macOS 下载路径。
- 区域根节点保留 `<section class="mobile-section" id="mobile" data-tone="light" aria-labelledby="mobile-title">`；实际标题保留 `id="mobile-title"`，导航锚点继续指向 `#mobile`。
- 移动端样式独立位于 `website/mobile.css`，由 HTML 的 `<link>` 直接引入。不要把移动端样式写入桌面模块，也不动态请求 HTML 片段；直接打开 file URL 与禁用 JavaScript 时仍需有完整内容。
- 新真实图片放 `website/assets/mobile/`，首次加入文件时再创建目录；建议文件名包含功能、日期或版本，来源说明记录完整路径。当前章节沿用 `website/assets/mobile-reader.webp`、`mobile-practice.webp`，这些仍是**原型预览**，不得重命名或换个标签冒充真机实拍。
- 预留 `[data-mobile-download]` 作为未来移动端安装按钮约定；当前页面没有移动端下载链接。核实真实公开或测试渠道后才使用该属性，说明对应发布状态。
- `website/downloads.js` 仅负责 Windows 和 macOS，移动端不接入该脚本的两平台属性。
- 原型与正式画面之间的状态区分要出现在用户可见文案中，不能只藏在源码注释或交接文档。
- 官网保留现有的大图统一放大功能。接手时沿用现有图片触发方式即可，不另建与阅读、语音或同步业务相关的依赖。

Mac 端 AI 的修改范围限于该 HTML 标记段、`website/mobile.css`、`website/assets/mobile/` 及移动端素材来源说明。本交接不要求修改 Windows/macOS 的业务、下载脚本或发布配置。

## 最终交付清单

- 真实截图与来源说明。
- 明确发布状态和真实渠道；没有渠道则保留“开发中”。
- 当前可用功能与必要限制的精简介绍。
- 如有下载按钮，核实链接可访问、平台正确、渠道状态一致。
- 桌面、平板和手机宽度的视觉检查；无横向溢出、图片缺失或新增运行异常。
- `#mobile` 区域替换记录与本文件的验收记录。
