# Windows 界面主题与 APP 图标统一调整计划

日期：2026-10-30。

状态：用户已确认交互原型并授权实施。主题范围保持阅读室手动选择、设置等窗口跟随系统；实施与验证结果见 [实施记录](./windows-theme-icon-unification-implementation-2026-10-30.md)。本地修改尚未发布。

## 1. 目标与判断

采用「墨绿品牌色 + 中性工具页面 + 纸感阅读区域」的统一方向。设置、历史、翻译浮窗、阅读、口语、笔记与复习之间，通过主操作、选中态和公共控件识别出同一个产品；阅读正文继续保留纸感底色和专用排版。

图标沿用圆角方形、墨绿底与浅色标记。用户在后续四版评审中选择 B「书页对话」，最终构图采用书页与对话尾角融合，表达从阅读进入口语；Windows 与官网使用同一母版。移动端改版另行安排。

当前差异有明确的实现来源：

| 区域 | 当前实现 | 本轮处理 |
| --- | --- | --- |
| 设置等工具窗口 | `src/styles.css` 全局靛蓝 `#4c5ff0`、蓝紫渐变、冷灰背景 | 统一品牌令牌，降低背景色彩存在感 |
| 阅读室书架、正文 | `reader.css` 的 folio + light 覆写墨绿 `#1f6b57`，暖纸背景 | 保留版式与纸感，品牌颜色从共同令牌派生 |
| 阅读室口语、笔记与复习 | `ReaderApp.tsx` 只在 shelf/reading 挂 folio；其余视图回到朱红主色和另一套控件表面 | 统一公共导航和控件的主色、状态与材质规则 |
| 快速复习 | 读取阅读室保存的 theme，使用旧的通用 `[data-theme]` 样式 | 纳入四主题校验，继续沿用现有主题来源 |
| APP、官网、商店图标 | APP 与官网母图相同；商店使用同目录的 Square/Store 资源 | 从同一可编辑母版生成并同步 |

以上结论依据仓库代码和现有图标文件。此前原生窗口捕获超时，最终效果仍需实施时的真实界面检查。

## 2. 视觉规则

### 品牌与主题

下表为本方案建议的基础值；实施阶段可以在保持统一方向的前提下，根据真实控件对比度微调。

| 用途 | 建议值 / 规则 |
| --- | --- |
| 浅色主操作、链接、选中态 | 墨绿 `#1f6b57` |
| 浅色悬停态 | 深墨绿 `#185646` |
| 浅色柔和选中背景 | `#e3f0ea` |
| 浅色品牌描边 | `#b9d8cc` |
| 工具页底色 | 中性浅灰 `#f4f5f2`，面板保持白色 |
| 阅读纸书底色 / 纸面 | 保留现有 `#F6F3EC` / `#FCFAF5` |
| 护眼背景 | 保留现有灰绿纸面，主操作使用共同的绿色规则 |
| 深色、OLED 的交互强调色 | 较亮绿色，候选 `#73c6aa`；保持各主题现有背景 |
| APP 图标 | 用户选定 B「书页对话」：墨绿实色底，浅绿左书页、白色右书页与对话尾角 |

用确定性计算检查了部分纯色组合：墨绿对白色约 6.37:1，墨绿对柔和选中背景约 5.43:1，候选深色绿色对 `#171A20` 约 8.62:1。这些数值仅证明基础色对可行，不代表半透明面板、全部状态或实际渲染已验收。

深色主题中，浅绿色填充按钮应搭配深色文字，不能继续沿用白字模板。悬停、按压、禁用、键盘焦点和文本选区必须逐项覆盖。

保留 `light / dark / sepia / oled` 的名称、保存值和切换顺序。设置页继续跟随系统，阅读室继续使用已保存的阅读主题，快速复习继续沿用阅读主题；本轮统一外观规则。

### 公共控件

- 主操作按钮、次操作按钮、输入框以现有尺寸为基础，统一边框、阴影、状态与圆角规则。紧凑控件使用 8px 圆角，较大操作及浮层使用 12px；实施时按同职责控件比较，避免仅按所在页面分配样式。
- 顶部导航和分段选择保留胶囊形；面板使用现有 12–18px 圆角。设置页保持表单的紧凑布局，阅读室保持现有三段顶栏和阅读布局。
- 阅读室四视图的公共顶栏采用一致的安静表面、选中态和焦点样式。内容专用区域可以保留阅读纸面、口语录音状态、复习卡片的区别。
- 保留 UI 字体与中英文阅读字体设置。颜色统一不伴随字体下载、排版重做或动画增加。
- 提示图标、文案与颜色共同表达成功、警告、错误等状态。

### 语义颜色

错误、危险删除、录音状态、托盘到期提醒、复习难度等级、发音评分及句法角色标注，先确认语义再决定是否改色。其中红色危险态、橙色警告及用于区分内容的标注应保留各自用途。蓝色内容标注可以继续存在。服务商标记、句法角色 `--clause-indigo`、声音辅助 `--sonic-teal` 和笔记朱批 `--notes-cinnabar` 分别核对用途，保留识别和内容区分能力。

清理对象包括旧品牌的渐变、按钮光晕、焦点环、选区、徽标及装饰性蓝色。不能对全部蓝色或全部朱红执行批量替换。

## 3. 修改范围与实施顺序

### 第一步：建立可对照的基线

1. 在隔离演示资料下记录设置、阅读室书架、正文、口语、笔记与复习的现有界面，以及当前图标的 16/32/48/128px 显示效果。
2. 为同一组主要按钮、选中态、开关、输入框和顶栏整理前后对照。设计预览使用实际组件与演示数据；现有 `scripts/gen-ui-preview.mjs` 只有旧静态模板和 `styles.css`，可辅助查看基础控件，不能代表当前阅读室和设置页。
3. 基于现有实现制作「设置页 + 阅读页 + 图标」的局部预览，先解决色彩关系，再应用到其他页面。无需等待新的业务需求或图标语义方案。

### 第二步：统一品牌令牌与基础状态

主要文件：`immersive-translator-windows/src/styles.css`。

- 增加少量共同品牌令牌，继续通过已有 `--accent`、`--accent-hover`、`--accent-active`、`--accent-soft`、`--accent-softer` 等名称接入现有组件，补齐各主题的 `--accent-hl`、`--accent-glow`、渐变及焦点环配套值。
- 令牌同时覆盖系统浅/深色、旧通用 `[data-theme]`、阅读室主题层；确保在「系统深色 + 阅读室浅色」等组合下不会继承错色。
- 将 `--accent-grad` 及硬编码品牌光晕、按钮阴影、选区和焦点环调整为共同规则。品牌图块可使用实色，不额外添加新的光效。
- 保留阅读纸面、护眼背景、深色背景与语义色。在现有主题块中整合覆写，避免继续在文件末尾叠加补丁。
- 同步更新此前描述“阅读室改动不得影响全局”的历史注释，使其准确反映本次有意统一的范围，继续遵守 CSS 作用域边界。

不新增主题状态管理器，不改设置持久化结构，也不引入样式库。

### 第三步：统一阅读室与工具窗口的公共外观

主要文件：`immersive-translator-windows/src/reader/reader.css`，以及实际存在品牌硬编码的窗口样式。

- 阅读室主操作颜色由共同主题令牌提供，处理 folio + light 的覆写，避免切到口语、笔记与复习就换主色。
- 将公共顶栏、同职责按钮和设置抽屉的规则覆盖阅读室四视图；folio 专属正文、侧栏宽度、播放条定位和窄窗契约继续留在原作用域。
- 核对 `SettingsDrawer.tsx` 的主题色样和标签，使其能对应真实主题；保留纸书、深色、护眼、纯黑等现有主题名称和切换逻辑。
- 不把 folio 标记直接挂到全部视图：它同时控制布局和组件尺寸，扩大作用域可能改变口语与复习布局。优先调整已有公共 `.shell-*` 和公共控件规则。
- 检查设置、历史、翻译浮窗、登录、引导、提醒卡、快速复习、录音直译、OCR 框选及错误兜底界面。
- 已确认需要关注 `reminder/reminder.css`、`quickreview/quickreview.css` 的蓝紫徽标，`views/onboarding.css` 的硬编码背景与浅蓝选中态，以及 `ErrorBoundary.tsx` 的蓝色按钮。局部录音红色、错误色保持语义。
- OCR 选框、尺寸标签等采用统一可见的强调色，保留截图背景变化时的辨识能力。

React 文件只有在品牌图或状态色无法通过现有 CSS 接入时才做局部修改；业务事件、导航、读取设置和语音流程保持现状。

### 第四步：生成并同步图标

最终可编辑来源：`prototypes/speaking-icon-concepts-2026-10-30/book-dialogue.svg`，采用用户已确认的 B「书页对话」。正式母版是 `src-tauri/app-icon.svg`，`icons/icon.png` 与官网品牌图均为 512×512。旧 A/文原型继续作为历史归档。

1. 将确认后的可编辑母版保存为 `immersive-translator-windows/src-tauri/app-icon.svg`，保持原型归档不变。
2. 保留选定的书页与对话尾角轮廓、墨绿底及浅绿/白色书页。小尺寸需要时单独微调笔画，不改变选定标记结构。
3. 使用项目已有 Tauri CLI 的 `icon` 命令从母版生成到临时输出目录。该 CLI 支持方形 SVG 或透明 PNG 输入与 `--output`，无需新增渲染依赖。
4. 先检查尺寸、格式、透明边缘和必要文件完整性，再按明确文件清单同步到 `src-tauri/icons/`。保留现有配置和打包脚本引用的文件名；默认生成器未输出的现有尺寸另行补齐。
5. 输出包含应用 PNG、ICO、ICNS、现有 Square/Store 图标、64px 与 `tray-icon.png`；正式 `icon.png` 和官网母图保持 512×512。Tauri CLI 的 `--png` 会切换为只输出 PNG 尺寸，补 64px 等文件时另用临时目录，保留全套生成结果。
6. 将同一 PNG 母图同步到 `website/assets/brand-icon.png`。官网已经采用深绿方向，本轮只同步品牌图及受影响的品牌素材；界面截图随实际修改更新来源说明。
7. 将 `scripts/make-icon.py` 更新为调用已确认母版的非破坏性生成入口，或提供明确的替代入口并停用旧脚本。旧脚本仍生成“双向箭头”，还会删除 Square/Store 资源，不能原样执行。

托盘真实来源是 `app.default_window_icon()`，到期状态再通过 `tray_badge.rs` 叠加红色徽标。验收应检查打包后的应用图标及动态徽标，单独替换 `tray-icon.png` 不足以更新运行时托盘。

MSIX 本地资源至少核对 `Square44x44Logo.png`、`Square150x150Logo.png`、`Square71x71Logo.png`、`Square310x310Logo.png`、`StoreLogo.png`，这些是 `pack-msix.ps1` 当前复制的五项。保留清单与包身份。

### 第五步：回归与交付

将样式和图标资源拆成两个可独立审查、回退的改动，附上真实界面前后对照、图标尺寸对照、资产生成入口与验证记录。仅在相关测试、视觉检查和构建核对完成后记录实施完成。

## 4. 验收矩阵

| 范围 | 必验组合 | 验收重点 |
| --- | --- | --- |
| 设置、历史、翻译浮窗、登录、引导、提醒、录音直译、错误兜底 | 系统浅色、深色；浮窗透明边缘 | 统一主色，文字、表单、警告、按钮可见，布局和窗口透明区域正常 |
| 阅读室 | shelf / reading / speak / vault × light / dark / sepia / oled | 公共品牌主色和控件规则一致；纸感、阅读字体、内容语义色正常 |
| 阅读室与系统混合主题 | 系统深色 + 阅读室 light/sepia；系统浅色 + 阅读室 dark/oled | 背景、文字、按钮前景、焦点和选区不串色 |
| 快速复习 | 四个保存的阅读主题 | 通用 `[data-theme]` 的颜色完整，控件和复习结果可见 |
| 公共交互 | default / hover / active / disabled / focus-visible，开关与选中态 | 按压不闪旧蓝紫，键盘焦点清楚，禁用态与内容可区分 |
| 阅读布局 | 1200px 常规窗口、1199/1019px 附近、960px 最小宽度；短窗口及专注模式 | 侧栏、播放条和顶栏仍可达，无遮挡或意外溢出 |
| 小工具布局 | 设置 560px 最小宽度、翻译浮窗 320px 最小宽度及各窗口配置下限 | 按钮和表单没有被新圆角、边框或间距挤坏 |
| Windows 缩放 | 100% / 125% / 150% | 文字、控件和窗口边缘清晰，小尺寸图标无多余边线 |
| APP 图标 | 16/32/48/128/256px；浅色和深色任务栏；桌面、托盘、开始菜单 | A/文仍可辨认，无白边、裁切、旧紫色小尺寸或模糊边缘 |
| 托盘提醒 | 无到期、存在到期；小图尺寸 | 红色到期徽标和底图可区分，徽标数量与逻辑正常 |
| 官网与 MSIX | 官网导航/favicon、包内 Assets 文件、应用 ICO | 母版一致、文件齐全、路径有效，资源是本次生成的版本 |

文字对比度目标至少 4.5:1，必要的控件边界和键盘焦点目标至少 3:1。半透明控件按合成后的背景检查；成功、录音、难度等状态继续有文字或图标提示。

使用现有浏览器预览验证渲染，并用 Windows 实际构建核对任务栏、托盘与安装包图标。浏览器演示截图与原生截图分别注明来源。

### 测试与构建

在 `immersive-translator-windows/` 执行：

```powershell
npx.cmd tsc --noEmit
npx.cmd vitest run src/core/readerTypes.test.ts src/reader/readerSettingsStore.test.ts src/reader/ReadingView.cloze.test.tsx src/reader/VaultPage.test.tsx src/views/LoginView.test.tsx
npm.cmd run build
```

若实际只改变 CSS，优先用视觉检查证明样式结果；上述现有用例用于回归主题数据和关联组件行为，不代表颜色已经通过视觉验收。若改动其他 React 文件，再运行该组件已有的相关测试，不为颜色赋值增加重复实现的单元测试。可执行现有 `node scripts/check-css-balance.mjs` 辅助检查 CSS 括号；该脚本未通过退出码表示所有错误，应读取其输出确认。

图标阶段执行本地 Tauri 构建，核对生成图标已嵌入新 EXE；具备构建产物后依照现有 `pack-msix.ps1` 核对本地 MSIX 的 Assets。构建或原生检查无法完成时，记录具体原因和剩余验收项。

## 5. 边界与后续发布

- 本轮计划范围：Windows 视觉样式、现有图标构图的配色、可复现的资产生成入口、官网本地品牌素材与相应验证文档。
- 保留现有业务逻辑、公共 API、数据与主题设置结构、包身份、更新机制及商店权限声明。
- 手机端实现与商店线上提交另行安排；当前手机原型和旧图标作为后续品牌同步项记录，不在本轮自动扩大修改范围。
- 本轮实施交付为本地可审查结果。发布时按 `docs/github-release-runbook-2026-10-30.md` 与 `docs/microsoft-store-update-runbook-2026-10-30.md` 执行版本、双通道出包、补签和商店流程。商店版应用内 updater 短路继续保留。
- APP 图标变化需要新构建与安装包更新才能到达用户；官网品牌图需要部署才能上线。计划文档或资源生成完成均不代表已经发布。

完成判定：用户可以从设置进入阅读、口语与复习，公共导航及操作始终表现为同一品牌；阅读正文仍有独立纸感；Windows、官网及 MSIX 本地图标来自同一母版，并且相关视觉与构建核对有实际记录。
