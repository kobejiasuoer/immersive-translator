## 2. 改造前后实测对比

| 指标 | 改造前 | 当前 |
|---|---|---|
| 首屏产品图（1440） | 1259×900（1.40，左右各裁 90px） | **1259×839（1.50，整窗完整）** |
| 功能配图（1440） | 688×900（0.76，竖条切片） | **688×459（1.50）** |
| 功能行高度 | 933px | **约 492px** |
| 整页高度（1440） | 8315px（约 9.3 屏） | **6995px（约 7.8 屏，−16%）** |
| 产品图来源 | 「交互原型 v0.1」双栏段落界面 | **运行中的 v0.9 应用实拍（句对主从）** |
| 图片体积 | 4 张约 1.6MB PNG | **5 张约 370KB WebP** |
| 390 视口横向溢出 | — | **无**（docW = 视口） |

根因不是 CSS 写错，而是 `<img height="900">` 的表现属性生成了 `height:900px`，**压过** `aspect-ratio`，`object-fit: cover` 于是横向裁切。加一行 `height: auto` 即恢复。

## 3. P0（阻断体验或可信度）

### P0-1 产品图比例失效 —— 已修复
- **现象**：首屏图 1259×900，功能图 688×900；截图里的句子被拦腰切断（"Most of us" → "of us"），移动端只剩 437px 竖切片。
- **改法**：`.hero-preview img, .feature-image img { height: auto; }`；比例统一到素材真实的 1.5。

### P0-2 截图是废弃原型 —— 已替换
- **原问题**：四张图带「交互原型 v0.1」角标，画面是**双栏段落对照**，而 Windows 的 `.pair` 与 macOS 的 `SentencePair` 都已是**单栏句对主从**；`reader-room-library.png` 与 `reading.png` 仅播放条状态不同，标签却写「文章与书架」。
- **处理**：直接驱动本机运行的应用，重拍了 5 张（阅读 / 内置文库 / 查词 / 笔记复习 / 口语场景），去掉窗口标题栏后统一为 1206×804（1.5）。
- **仍未解决**：书架页只有 1 本书，不适合做「先选文章」的配图，因此这一格改用**添加阅读内容面板**（内置文库 + 四种导入方式），更贴合该段文案。

### P0-3 首屏主 CTA 空转 —— 已修复
- **现象**：主按钮「看阅读室功能」→ `#reader`，目标就在下一屏。
- **改法**：主按钮「下载桌面版」→ `#download`；次链接「看阅读室功能」→ `#reader`。

### P0-4 四图并排画廊 —— 已删除
- **现象**：`.screen-band` 出血到 x=0，与 72px 页边距不对齐；第 4 张在视口右缘被切断；标签因各图宽度不同错位 304px；四个 `<button aria-pressed>` 点击只改自身宽度。
- **改法**：整块删除。三张图与下方功能行重复，删除后每张图在自己的段落里出现一次。

### P0-5 产品图没有窗口容器 —— 已修复
- **改法**：`.hero-preview img` / `.feature-image img` 统一 1px 边框 + 12px 圆角 + 分层阴影。**没有**伪造 macOS 红绿灯——截图自带应用顶栏，再套一层会变成两层窗口。

## 4. P1（明显影响转化与观感）

### P1-1 门槛信息全部后置 —— 未做，建议新增「开始之前」
- **现象**：免费开源、需要自备 API Key、阅读记录存本机——三条最影响决策的事实只出现在第 8 屏的折叠 FAQ 里。
- **改法**：在下载区之前加一个 `dl` 三列块（免费开源 / 自备 Key 或本地模型 / 数据留在本机）。首屏已先加一行 `Windows 与 macOS 桌面版 · MIT 开源 · 阅读记录保存在本机` 作为轻量前置。

### P1-2 下载区信息不足 + 全部跳 Releases 列表
- **已做**：指向 `/releases/latest`；Windows 卡补「安装包约 24 MB」；按钮文案改为「下载 Windows 版 / macOS 版」。
- **仍建议**：在 CI 里给最新 Release 额外上传一份**固定文件名**的安装包，站点就能用 `releases/latest/download/<固定名>` 直下。当前文件名带版本号，做不到稳定直链。

### P1-3 macOS 未公证提示 —— 已改
- **改法**：移进 macOS 卡片，放在版本要求下方，13px + 左侧细线，写明「首次打开需在系统设置 → 隐私与安全性中允许」。CTA 保持干净。

### P1-4 901–1024 仍双栏 —— 已改
- **改法**：功能行统一在 **1024px** 堆叠（1024 实测单列 885px）。

### P1-5 移动菜单的键盘死路 —— 已修
- **现象**：`.menu-toggle` 在 DOM 里位于 `<nav>` 之后，键盘用户打开菜单后 Tab 直接跳到 `<main>`。
- **改法**：按钮移到 `<nav>` 之前（视觉顺序用 `order: 3` 保持最右）；文案「菜单 / 关闭」切换；点击页头外部关闭。

### P1-6 字重在 Windows 上塌陷 —— 未做
- **现象**：全文用了 550 / 650 / 680 三档字重。Windows 没有 Noto Sans SC，落回微软雅黑，而雅黑只有 400/700 两档——所有中间字重被就近取整，`.text-link` 的 550 读起来像小字说明。
- **改法**：最彻底是按页内实际用字做**子集化自托管**（本页约 300 个汉字，WOFF2 约 80–120KB）；退一步是把标题统一到 700、正文 400。

### P1-7 深色区三块「像输入框」的方块 —— 已修
- **改法**：改为编号条目（01/02/03）+ 细分隔线 + 左对齐。

### P1-8 标题层级与节奏 —— 已改一半
- **已做**：功能行标题降为 `h3`（40px），建立 h2(48) > h3(40) 的层级。
- **仍建议**：三组「四字，四字。」的对句至少换一组为陈述句或带具体数字。

### P1-9 功能图在 688px 下仍不可读 —— 部分缓解
- **现象**：1206 宽截图缩到 688（0.57×），界面正文 14px 变 8px，只能看出「有这么一个界面」。
- **仍建议**：每个功能行再配一张 **1:1 细节图**（688×459 从原图裁切、不缩放），例如查词卡 + 上下文两句。整窗图留给首屏建立「这是应用」的印象。

### P1-10 分享卡片 —— 已做，差域名
- **已做**：补齐 og:type/site_name/title/description/image 与 `twitter:card`，并生成了 1200×630 的 `assets/og-cover.png`。
- **注意**：`og:image` 必须是**绝对 URL**，当前写的是相对路径，部署域名确定后要替换（文件里留了 TODO 注释）。
