# 语音设置与可用性修复

日期：2026-11-03。

## 已确认的问题

1. `voice` 配置段存在不等于语音已开放。三项能力全部为空时，旧界面仍显示“部分可用”。
2. 登录沉浸云会强制覆盖用户已选择的讯飞服务；云能力未开通时会让原本可用的语音输入、评分变为不可用。
3. 讯飞设置测试仅发送带签名的 HTTPS GET，没有 APPID 或真实音频请求；旧实现将 404、429、500 等也判为成功，不能据此证明业务可用。
4. 练习接力的转写、评分绕过服务选择与能力守卫。
5. 账号切换后的能力缓存、TTS 连接和额度失败状态可能沿用旧账号。
6. 服务端 TTS/ASR 能力原先按配置下发，没有检查真实可路由凭据；批量、流式 ASR 共用能力列表可能误导具体入口。

## 本次调整

- 页面采用单栏：选择服务、当前状态、朗读/语音转文字/跟读评分三项用途与操作。高级凭据、额度及批量测试按需展开。
- 分开呈现未登录、登录失效、检查失败、未开放、额度耗尽和用户关闭。停止“登录即用”和盲目推荐的文案。
- 本地测试服务连接时显示实际地址及环境提示，避免把本地 `8090` 的状态误认为生产域名状态。
- 保留用户语音服务选择，登录不再自动改成沉浸云。此行为替代 `voice-cloud-decisions-2026-10-28.md` 决策 1，避免未开通的云服务覆盖现有讯飞。
- 云端朗读可真实试听，收到有效音频并完成播放才显示通过。识别、评分使用打包的英文 PCM；没有英语批量识别能力时不上传英文样本，评分关闭时不执行评分测试。
- 讯飞现有探测明确称为“检查连接”，不将连接检查当成服务可用；HTTP 失败不再点亮绿灯。凭据继续沿用现有加密存储。
- 练习接力复用现有讯飞与网关消费接口；能力禁用时不读取或上传音频。
- 能力缓存按账号隔离并丢弃账号切换中的响应；TTS 旧账号连接和排队任务会取消；阅读室额度回落有有限有效期，可恢复。
- 服务端按实际候选下发能力，新增 `voice.asrStreamingLanguages`、`voice.asrBatchLanguages`。旧 `asrLanguages` 保留可路由语种并集；新客户端缺字段时兼容旧字段，明确空数组保持关闭。

## 线上核对与配置修复

生产入口：`https://www.prismspace.online/admin/`。

- 三条语音凭据的类型分别为 `tts/asr/ise`、provider 均为真实 `xfyun`，已启用。
- 实际管理拨测通过：TTS 177ms、批量 ASR 202ms、ISE 356ms。没有读取或导出凭据明文。
- 原生产配置：TTS、流式 ASR、批量 ASR、ISE 引擎均为空，ISE 总开关关闭。管理拨测绕过引擎选路，因此“凭据拨测成功”与“用户能力全部未开放”可以同时成立。
- 已保存四项 `xfyun` 引擎绑定并开启 ISE。重新加载管理台后再次从服务器读回，确认配置持久化。默认音色、音色表、语种及兜底引擎沿用既有缺省。
- 当前原 APP 为调试构建，界面实际显示连接 `http://127.0.0.1:8090`，不消费上述生产配置。普通用户验收须用正式构建连接生产域名，用户正在切换并登录。
- 管理台 TTS 拨测会丢弃音频；ASR/ISE 使用静音，仅验证协议和授权。不能据此声称实际播放、真实转写或正常评分全部通过。

## 完成生产验收的必要步骤

1. 登录 [生产管理台](https://www.prismspace.online/admin/)，进入「配置 → 上游凭据」，核对每项能力的已启用凭据、上游授权和额度。不要仅开启能力开关。
2. 使用凭据行内「拨测」确认上游可用，再进入「配置 → 语音引擎」设置 TTS、流式 ASR、非流式 ASR、ISE 开关及引擎。参考附加服务端仓库 `docs/runbook.md`。
3. 部署本次服务端与客户端修改后，用普通账号重新获取能力。
4. 在设置页试听朗读并运行真实识别/评分测试，随后验证阅读室朗读、口语陪练输入、录音直译和练习接力；失败需保留明确的用户提示。
