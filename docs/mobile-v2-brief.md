## 0. 一句话

v1 把「复习 + 收词 + 轻阅读」装进口袋之后，v2 把 Mac 端新落地的**语音三件套**（口语陪练、影子跟读、录音直译）对齐到手机形态，并补上「复习触点」的移动对应物：**5 个 Tab（今天 / 练 / 书架 / 生词 / 我的）+ 按住说话 + 通知清 1 张卡**。iPhone 优先，交互全部按 iOS 规范；`<520px` 自动脱壳全屏。

## 2. 关键交互决策

1. **语音三件套独立成「练」Tab（5 Tab IA）**：不塞进「今天」。理由：复习是每日必做（排程驱动），练是自选动作（意图驱动）；混排会让首页大数字失焦，也让练的三个入口埋两层。今天首页保留一排「练一练」快捷入口承接发现。
2. **按住说话是唯一录音手势**：陪练、跟读共用同一交互语言（对应 Mac 端按住 Cmd 说话的触屏翻译）；按下 <350ms 视为误触，toast 提示手势。实现注意：录音态重渲染会替换按钮元素，**pointerup 必须挂 document 委托**（原型里已按此实现，是移动端最容易踩的坑）。
3. **AI 气泡 = EN 主体 + 中文弱提示行**（灰、小、衬线）：与 Mac SpeakLogic 的 EN/ZH 两行格式同构；中文提示不折叠交互，卡住了另给「看中文提示」chip（toast 演示）。AI 接话后自动 TTS 播报；「简单」难度播报语速 0.8×。
4. **跟读不达标才有词级着色**：过关只给分数胶囊，失败才把 ISE 词级结果标红并给三按钮（再试 / 领读·慢速 / 跳过）——与 Mac P4 的「不达标 → 词着色 → 领读自动重开麦」循环一致；领读 = 0.75× TTS，读完自动回到待录态。
5. **录音直译以「字幕流」为第一公民**：手机不做悬浮窗（Mac 的字幕窗对应物是全屏字幕流），每句一张卡（时间戳 + EN + ZH），「正在说」用半透明打字态表达流式转写；结束才出现导出抽屉，默认导出双语 Markdown、不保留音频。
6. **通知触点 = 1 卡快速复习，不等于复习流**：横幅文案给具体数字（「8 个生词到期」）与预期时长（「5 分钟」），动作二选一（清一张 / 稍后）；快速复习单卡完形 → 判分 → 评分 → 「已清 1 张」即走。对应 Mac P7 的菜单栏角标 + 迷你窗，移动端用本地通知实现。
7. **从读到练**：阅读页播放条加跟读按钮，以当前句为起点开跟读——阅读内容直接变成口语材料，不要求用户去练 Tab 重新选文章。

## 3. 实现注意（给 M3/M4 之后的语音里程碑）

- 判分 / SRS / 词级 diff 内核与 v1 同一份纯函数；语音侧新增的纯逻辑（VAD 分句、评测解析）在 Mac 端 `ReaderCore`（`LiveCaption.swift` / `SpeakLogic.swift` / `ShadowAssessController.swift`）已有 Swift 实现，移动端需要对应 TS/Rust 移植或经插件复用讯飞链路。
- 按住说话的手势在 iOS WebView 需 `touch-action: none` + `preventDefault` 防滚动/长按菜单（原型 CSS 已带）；录音态 UI 更新走状态机（idle→rec→asr/assess→result），**不要在录音态整层重渲染后仍依赖旧元素监听**。
- TTS 播报排队依赖 `onend` 链（逐句推进同 v1 阅读层）；系统 TTS 在真机上注意静音开关与 audio session（Mac 端已有结论）。
- 通知横幅的原型只是视觉模拟；真机走 `UNUserNotificationCenter`，点通知 deep-link 进快速复习路由（`#demo=quick` 的等价物）。
- 录音直译的打字态在实现里是真实 ASR partial 流（原型用定时器模拟）；收句时机以 VAD 静音阈值为准，与 Mac `LiveCaption` 同一套经验值。
