# 移动端账号与设置检查 · 2026-11-04

依据用户提供的四张 iPhone 截图及当前移动端源码。移动端语音与模型服务统一采用账号登录和服务器路径；供应商、引擎和手动凭据不属于移动端学习设置。

## 本轮已调整

| 原问题 | 实际修改 |
| --- | --- |
| 左上「账号与同步」与面板「账号与学习设置」命名不同 | 统一「账号与设置」，让入口覆盖账号与设备偏好 |
| 账号内「阅读设置」实际跳到「外观」，不能调整正文 | 打开真实的阅读设置子抽屉，可调整字号、行距、主题、语速与译文显示；关闭后回到账号面板原位 |
| 账号内语音入口打开供应商凭据页 | 打开「语音与朗读」子抽屉，与语音页面共用账号下发的声音、示范语速和麦克风权限组件 |
| 子抽屉默认在 `.app` 内，层级低于挂在 body 的账号面板 | 账号子抽屉使用 body 及 130/131 层级；打开时父面板 inert |
| 已登录用户邮箱主、副行重复 | 未设置昵称时，主行使用邮箱用户名，副行保留完整邮箱 |
| 完整同步状态卡加全宽「立即同步」挤占学习设置空间 | 同步按钮放在状态行右侧；离线只显示待同步原因；时间缩为「刚刚」或「今天 HH:MM」；首次同步前显示「准备同步」 |
| 练习统计使用任务数量，空任务和草稿也算一次 | 「次作答」仅统计已完成反馈的回答 |
| 只读过第一句的文章没有被计入阅读记录 | 已产生阅读位置或 lastReadAt 即计入，包含单句短文 |
| 登录表单说支持手机号，但输入是 email，服务契约使用邮箱 | 统一邮箱标签、键盘和自动填充；更改邮箱后撤销上一邮箱的验证码就绪状态 |
| 「找回密码」要求输入新密码，实际只执行 OTP 登录 | 改成真实的验证码登录，删去无服务端支持的新密码输入和重置成功暗示 |
| 「退出后继续本机学习」容易让人误以为账号数据进入游客空间 | 明确资料仍属于当前账号，退出切换本机试用，重新登录同一账号后继续 |

## 建议下一步明确

1. **学习方向应有实际效果。** 当前 `settings.goal` 的消费仅在账号摘要与方向选择页，没有参与书架、推荐或练习的选择。建议接入内容推荐，或明确这是偏好记录，避免「让下一篇更适合你」成为空承诺。
2. **账号应显示服务权益。** 已有 `account.plan` 与独立的 `/v1/me/quota` 服务接口，适合用简短状态展示可用权益、剩余额度及兑换入口。用户需要判断能否继续学习，无需理解供应商名称。
3. **提醒入口须保持一套真实状态。** 检查时另一路正在落地 `studyNotifications` 原生排程；旧 `components/vault/ReminderSheet.tsx` 仍直接写 `daily=true` 并显示成功提示，需要与新权限和排程状态统一，确认拒绝权限、排程失败、App 关闭及点击通知都与文案一致。此文不把源码中的新排程当作真机通知验收。
4. **同步状态按账号隔离。** `MobileSync.status` 当前是实例级内存状态，账号切换没有单独清空上一账号的同步时间和失败文案。建议将显示状态绑定当前账号，避免登录其他账号时短暂显示旧时间或旧错误；数据层本身已有 profile/generation 守卫，不等同于发现了数据串号。
5. **设置继续扩展时改成完整页面。** 本轮通过缩短同步区减少滚动，保留现有抽屉风格。如果后续加入权益、密码管理和兑换，完整「账号与设置」页面会更合适。截图中内容从固定标题下方滚动进入是现有滚动区行为，不能仅凭截图断言内容丢失。
