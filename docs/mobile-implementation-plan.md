## 1. 前置条件与预算（开工前必须解决）

### 1.1 开发机：Mac 已具备（2026-09-12 确认）

**iOS 开发无法绕过 macOS + Xcode**（签名、模拟器、真机调试、构建、截图、上传都依赖它）。已确认手头有 Mac，随时可切。双机分工：

| 在 Windows 上做 | 在 Mac 上做 |
|---|---|
| 全部 React UI 开发（Vite dev + 浏览器 iPhone 视口，热更新快） | `tauri ios dev`（模拟器/真机跑） |
| 共享 core 抽取、单测（vitest） | 原生插件（TTS/Share Extension）的 Swift 代码 |
| contracts schema 演进、桌面端联动 | 构建、签名、截图、上传 App Store Connect |
| 原型迭代 | TestFlight 管理 |

M0 第 1 周在 Mac 上完成一次性配置：Xcode 安装（约 12GB）、`xcode-select --install`、Apple ID 登录。

### 1.2 账号与证书

- **Apple Developer Program：$99/年（约 ¥700）**。个人账号即可；真机调试在免费 Apple ID 下也能做（签名 7 天过期），但 TestFlight 和上架必须付费账号。
- 个人 vs 公司账号：v1.0 无支付无云服务，**个人账号足够**；商业化（IAP）后个人账号也能收（Apple 代扣税）。若后续要公司主体再迁移（App 可转移，但流程慢，能早就早）。

### 1.3 启动预算汇总

| 项 | 金额 | 必要性 |
|---|---|---|
| Apple Developer Program | ¥700/年 | 必须（第 2 周购入） |
| 域名（隐私政策+备案载体+未来官网） | ¥50–100/年 | **关键路径**：第 5 周前买好，与定名绑定（§6.3） |
| 国内云最低配+备案服务号 | ~¥100–300/年 | **关键路径**：随域名一起第 5–6 周办，是提交备案的前提 |
| 商标注册（第 9/41 类，定名后办） | ~¥300/类·10 年 | 不阻塞上架，早申请早保护（§7.3） |
| 软件著作权（国内安卓商店才需要） | 自办免费（约 60 工作日）/ 代办 ¥300–800 | 暂缓，上国内安卓渠道前再办 |
| **合计（Mac 已有，无硬件支出）** | **首年约 ¥1200–1500** | |

## 2. 工程与仓库结构

### 2.1 目标结构（monorepo 演进）

> 拍板注（2026-09-12）：方案 B 闭源后，本仓库将在 M1 转为 **GitHub 私有仓库**，monorepo 结构不变（落地清单见 §7.2）。

现状：`immersive-translator-windows/`（独立 npm 项目，core 纯逻辑混在 `src/core`）、`immersive-translator-mac/`（Swift）、`contracts/`（schema v1）。

目标：抽共享包，三端消费同一份逻辑。

```
immersive-translator/
  contracts/                      # schema（已有，继续作为跨端契约的单一事实源）
  packages/
    reader-core/                  # ★ 新建：纯 TS 核心，零 DOM/零 Tauri 依赖
      src/
        readerTypes.ts            # 数据模型（从 windows/src/core 迁入）
        readerSrs.ts              # SRS 调度
        recallJudge.ts            # 完形/听写判分（新增，按 recall brief 实现）
        sentenceSplit.ts chunkAnnotate.ts
        dictCard.ts readerDict.ts articleBuilder.ts
        glossaryParser.ts languageDetect.ts
        providerPresets.ts promptBuilder.ts paragraphTranslate.ts
      __tests__/                  # vitest（现有单测随迁，全部保绿）
  immersive-translator-windows/   # 改为依赖 workspace: packages/reader-core
  immersive-translator-mac/       # Swift 侧继续对齐 contracts
  immersive-translator-mobile/    # ★ 新建：Tauri 2 mobile 工程
    src/                          # React UI（mobile-v1 原型转写）
    src-tauri/
      src/                        # Rust：复用/移植 reader_store.rs（SQLite on mobile）
      ios/                        # tauri ios init 生成的 Xcode 工程
        ShareExtension/           # （M4）原生分享扩展 target
      gen/                        # TTS 等自写插件
  prototypes/ docs/
```

包管理：根目录加 `pnpm-workspace.yaml`（pnpm workspace）。抽取原则：**先搬文件+改 import+跑绿单测，不做任何行为修改**，单独一个 PR。

### 2.2 schema 演进（v1 → v1.x）

移动端只需要可选字段增量（向后兼容，`schemaVersion` 不动）：

- `VocabWord.updatedAt?: number`——文件互导/未来同步的合并依据（LWW）；
- 导出文件格式 v0 spec：`{ format, version: 1, exportedAt, device, articles: [...], vocab: { words, reviewLog } }`；
- 合并规则：词条按 `id` 命中 → 取 `updatedAt` 新者；文章按 `id` → 进度取 `max(sentenceIdx/percent)`，句对 `zhState=edited` 优先；未命中 → 整条新增。

### 2.3 Rust 存储层策略

`reader_store.rs` 的 10 个 command 在移动端复用（Tauri 2 mobile 支持 Rust command）。差异点：Windows 侧的存储路径/文件名常量抽出为 per-platform；SQLite（若用）或 JSON 文件存储在 iOS 沙盒 `Application Support`。**M1 里先做 iOS 侧读写冒烟，再谈复用深度。**

## 3. 里程碑开发计划

> 工期按业余时间每周 10–15 小时估算。每个里程碑有独立验收标准，可单独暂停。

### M0 · Spike 验证（2 周）——Go / No-Go 闸门

> **2026-09-12 进展**：spike 工程已搭好（`immersive-translator-mobile/`，React 界面 + Tauri 2 工程），Windows 侧已验证 `npm run build`、`cargo check`、浏览器全链路（压测文章 600 句/12450 节点渲染 103ms、点词查词→收藏→高亮联动、完形判分）。
> **Mac 侧执行手册：`docs/mobile-spike-runbook.md`（照着敲，预计 1–2 天出结论）。**

目的：在写任何正式代码前，把 Tauri 2 iOS 最大的不确定性全部真机验证。

前置管理项 S0：**锁定 Bundle ID**（与产品名无关，如 `com.<个人标识>.reader`；上架后不可改，`tauri ios init` 一开始就用它）。

| # | 验证项 | 通过标准 |
|---|---|---|
| S1 | `tauri ios init/dev` 在模拟器+真机跑通 hello world | 真机 3 分钟能出首屏 |
| S2 | 长文滚动性能：渲染 600+ 句对（双语+词块高亮） | 滚动不掉帧（Instruments 看）、首屏 < 1.5s |
| S3 | 自写 TTS 插件（AVSpeechSynthesizer） | JS 侧可播放、可暂停、`onend` 回调链可用（逐句连播依赖它） |
| S4 | BYOK HTTP：WebView 里 fetch 直连 LLM API | 明确走 fetch 还是 Rust http 插件（CORS 结论写进 spike 报告） |
| S5 | 文件导入：document picker 读 .json | 真机能从「文件」App 选取并解析 |
| S6 | Share Extension 预研：Xcode 加 Extension target + App Group | 扩展能写入共享容器、主 App 能读到。**已知 Tauri 社区对 app extensions 反馈较多，此项若失败 → P0 降级为剪贴板检测，扩展移 P1** |
| S7 | 原型 CSS 兼容性：`color-mix/backdrop-filter/100dvh` 在 iOS 16.0 WebView | 确定最低版本；必要时替换 `color-mix` |

**No-Go 判据**：S1/S2/S5 任一失败，或 S2 性能不可接受且无解 → 切 Expo React Native（`packages/reader-core` 全量复用不变，UI 用 RN 重写——原型期间 UI 本来就是为触屏重新设计的，沉没成本可控）。

产出：`docs/mobile-spike-report.md`（每个 S 项结论 + 证据截图）。

## 4. 真机调试指南（开发完之后怎么调）

### 4.1 一次性配置

1. Mac 上装 Xcode（App Store，约 12GB）+ `xcode-select --install` 命令行工具；
2. Xcode → Settings → Accounts → 登录 Apple ID（免费即可开始真机调试）；
3. iPhone：设置 → 隐私与安全性 → **开发者模式**（iOS 16+，打开需重启）；
4. 数据线连 Mac，Xcode 首次识别设备 → 信任开发者证书：iPhone 设置 → 通用 → VPN与设备管理 → 信任；
5. 免费 Apple ID 签名 **7 天过期**（每周重装一次，最多 3 台设备）；付费账号签名 1 年 + 100 台测试设备。**建议第 1 周就买付费账号**，省去反复重签。

### 4.2 日常调试循环

```bash
# Mac 上（immersive-translator-mobile/）
npm run tauri ios dev            # 模拟器
npm run tauri ios dev -- --open  # 连接的真机（自动选择）
```

- **UI 层调试**：改 React 代码热更新即时生效（和桌面开发体验一致）；
- **WebView 检查器**：Mac Safari → 设置 → 高级 → 勾选「开发菜单」→ Develop → [你的 iPhone] → [WKWebView] → 可看控制台/DOM/网络——**这是手机端排错第一工具**；
- **Rust/原生层日志**：Xcode console（`os_log` 输出）；插件 Swift 代码里用 `NSLog`/断点；
- **性能**：Xcode Instruments（Time Profiler / Core Animation FPS / Leaks），重点盯 M3 的长文滚动；
- **网络抓包**：Mac 上用 Charles Proxy，iPhone 设 Wi-Fi 代理（BYOK 调 provider 时用）。

### 4.3 Windows ↔ Mac 双机协作

- 代码走 git（Windows 写 UI/逻辑 → push → Mac pull → 真机验证）；
- 建议 Mac 上也跑 `npm run dev`（浏览器模式）做快速预览，真机只在里程碑节点验证；
- 或者反过来：远端开发桌面（VS Code Remote SSH 到 Mac）可以单人在 Windows 屏幕上完成全部流程——可选优化。

### 4.4 常见坑预告

| 症状 | 原因/解法 |
|---|---|
| 真机安装报「无法验证应用」 | 证书未信任（4.1 第 4 步）或签名过期（免费账号 7 天） |
| `tauri ios dev` 真机不出现 | 检查 iOS 部署目标 ≤ 设备版本；Xcode 里手动 run 一次生成的工程 |
| WebView 控制台看不到 | Safari 开发菜单没开，或 WKWebView 未启用 inspector（默认开） |
| 键盘弹起遮挡输入框 | 完形/听写输入做 `visualViewport` 适配（原型已按 iOS 规范设计，实现时验证） |
| TTS 没声音 | 真机静音开关、或 AVSpeechSynthesizer 的 audio session 类别配置错误 |

## 5. TestFlight 内测

- **内部测试**：App Store Connect 团队成员（最多 100 人），构建上传后立即可测，**无需审核**——这是你自己的日常真机分发通道（从此不用 7 天重签）；
- **外部测试**：最多 10,000 人，需一次 **Beta 审核**（通常 <48h，比正式审核松）；
- 上传方式：Xcode → Product → Archive → Distribute App → App Store Connect（或 Transporter app 拖 .ipa）；
- 内测目标：找 10–30 个真实用户（朋友/社群），跑 2–3 轮构建，收集：复习流完成率、查词链路是否顺、TTS 音量/语速反馈、崩溃（MetricKit/反馈表单）；
- 每轮内测 3–7 天，修完再上一轮；至少一轮「真实通勤场景使用」再提审。

## 6. App Store 上架全流程

### 6.1 时间轴（首次提审前）

| 周 | 事项 |
|---|---|
| T-3 周 | 定名（见 §12）、注册域名、隐私政策页上线（GitHub Pages 即可）、准备截图素材 |
| T-3 周 | App Store Connect 创建 App 记录（Bundle ID、SKU、名称占位） |
| T-2 周 | App 图标定稿（1024×1024，无圆角无 alpha）、截图制作（6.9"/6.5" 各 3–5 张，可用模拟器截图 + 模板加工） |
| T-1 周 | 填元数据：名称（30 字）、副标题（30 字）、关键词（100 字符）、描述、分类（**建议主分类 Education**，副 Productivity）、年龄分级（4+）、隐私营养标签 |
| T-1 周 | 出口合规：`Info.plist` 加 `ITSAppUsesNonExemptEncryption = false`（仅 HTTPS，豁免） |
| T-0 | 提审（一般 24–48h 出结果，节假日更久；被拒→改→重提，预留 2 轮往返） |

### 6.2 审核重点与对策（针对本 App）

| 条款 | 风险 | 对策 |
|---|---|---|
| **2.3.7 仿冒/误导名称** | 现名 ImmersiveTranslator 与「沉浸式翻译」撞名撞功能 | **上架前必改新名**（§12 拍板）；名称/图标/关键词都避开「沉浸式翻译」 |
| **4.2 最低功能**（WebView 壳） | 纯网页套壳被拒 | 我们有原生功能背书：Share Extension/App Group、本地通知、Keychain、系统 TTS；审核备注里主动说明 |
| **5.1.1/5.1.2 隐私** | 无隐私政策、数据声明不实 | 隐私政策 URL 必填；v1.0 无服务器无账号 → 声明「不收集任何数据」+ 本地存储；BYOK 时文本直连用户自选服务商要在政策里写明 |
| **2.1 完整度/崩溃** | 崩溃/明显 bug 直接拒 | TestFlight 轮次保证 |
| 4.0 设计 | 丑不至于拒，但影响过审体验 | 原型已有成熟视觉系统，风险低 |
| 元数据 | 截图与实际不符 | 截图取自真实构建 |

**v1.0 没有登录、没有支付、没有 UGC**，这三类高频雷区天然规避。首次上架越简单越好——登录/IAP/云服务全部放到 v2.x 再加（届时才触发 Sign in with Apple、账号注销、IAP 抽成等义务）。

### 6.3 中国区首发与 ICP/App 备案（关键路径 ⚠）

2026-09-12 拍板：**首发中国大陆区**。备案因此进入关键路径，倒排如下：

**依赖链：定名（≤第 5 周）→ 买域名+国内云（第 5–6 周）→ 提交 App 备案（第 6 周）→ 备案通过（第 7–10 周，常见 1–3 周，最长约 20 个工作日）→ 提审（第 19+ 周）**。备案与 M2–M5 开发完全并行，不影响总工期；但**名字若拖过第 6 周，备案顺延，提审就被顶住**——这就是定名截止期的由来。

备案要点：

- **政策现状**（2024 起强校验）：中国大陆区 App Store 对新 App 必须填写 ICP/App 备案号，且 App Store 简体中文名称必须与备案信息一致（苹果后台自动校验）；
- **载体**：域名 + 国内云服务商最低配（阿里云/腾讯云轻量，百元级/年）；隐私政策页可托管在同一域名下；
- **主体**：个人（身份证）可办；备案填的 App 名称 = 上架名，平台 iOS，需 Bundle ID（M0 已锁定）；
- v1.0 免费无支付无经营性内容，个人备案天然合规；即便 App 无自有服务器，按苹果现行执行口径联网 App 一律要求备案号，**不赌免备案的空子**；
- 备案号到手后填入 App Store Connect「App 信息」，再对中国区提审；其他区域（美/日/港）可同期开放，无需备案。

**连带影响**：域名从「不急」升级为第 5 周前必须就位（备案以域名+云服务器为载体），且最好与产品名同源（域名 ≈ 品牌名）。

### 6.4 上架后

- 版本节奏：小步快跑，0.x 期每 2–4 周一个版本；
- 用户反馈：TestFlight 反馈表单 + GitHub Issues（开源仓库天然承担）+ 邮箱；
- 崩溃监控：**MetricKit**（原生框架，无第三方 SDK，隐私友好，符合产品调性）；
- 数据指标（本地、不上传）：留存、复习完成率——用 TestFlight 问卷定性收集为主。

## 7. 开源策略（已定：方案 B，客户端闭源）

### 7.1 决定与边界

2026-09-12 拍板：**客户端（Windows / Mac / iOS / Android）全部闭源，先不开源；未来服务端同样闭源。**

需要知道的法律事实：现有 GitHub 仓库在公开期间以 MIT 发布，**已授予的授权无法撤回**——转私有之前克隆过代码的人，对其手中的历史版本永久享有 MIT 权利。转私有只是切断今后的获取与传播；对个人项目而言实际风险很低（历史代码不含服务端与商业化逻辑）。

### 7.2 落地清单（不紧急：建议 M1 顺手做，硬截止 M7 提审前）

> 2026-09-12 补充讨论：项目当前无人关注，公开/私有的**当下**实际差别 ≈ 0，且随时可逆——本清单不具紧迫性。仍建议早些（M1）顺手执行的真实理由有二，都与「有没有人看」无关：
> ① **上架前的暴露面**：仓库现名 ImmersiveTranslator 与「沉浸式翻译」商标撞名，上架宣传后仍公开源码，等于给换皮者现成素材、给投诉方现成靶子；
> ② **省掉两套仓库纪律**：提前转私有后，v2.0 的服务端代码、定价等商业内容可直接进 monorepo，不必维护「公开客户端仓 + 私有服务端仓」两套边界。反向也成立——将来想拿开源做冷启动素材，随时可再公开（届时建议只公开清理后版本或 `reader-core` 引擎层）。

- [ ] GitHub 仓库 `kobejiasuoer/immersive-translator` → Settings → Danger Zone → **Change visibility → Private**（stars/issues 历史保留，不再对外可见）；
- [ ] 根目录 `LICENSE`（MIT）删除，`package.json` 的 `license` 字段改为 `"UNLICENSED"`（私有仓库无开源义务，保留 MIT 文件反而造成误导）；
- [ ] README/文档中「开源」相关措辞清理；
- [ ] 用户反馈渠道改为 App 内反馈入口 + 邮箱（不再依赖 GitHub Issues——仓库私有后外部用户提不了 issue）。

### 7.3 代价与保留选项（如实记录，不翻案）

- **放弃**：社区 issue/PR 的免费贡献、开源社群的自然曝光（调研 §5 的冷启动渠道之一）。冷启动改靠内容运营（小红书/即刻/知乎的英语学习社群）+ TestFlight 口碑传播；
- **保留后悔药**：私有仓库随时可重新公开。若未来想开源，建议只开源 `packages/reader-core`（判分/SRS/分句引擎层），完整 App 保持闭源；
- **山寨对策不变**：商标注册（第 9 类软件 + 第 41 类教育，定名后 2 周内提交，约 ¥300/类·10 年，个人可网上申请）+ App Store 版权投诉通道；闭源本身并不阻止功能模仿——真正的壁垒仍是数据锁定期（SRS 进度、词库资产）与迭代速度。

## 8. 商业化设计（营收获利）

> 2026-09-12 拍板确认：v1.0 免费、v2.0 Pro 订阅。以下为既定路线的执行细节。

### 8.1 原则

- **本地闭环永久免费**：阅读、查词、收藏、SRS 复习、文件互导、BYOK 翻译——这些是获客与口碑的根基，永不设限；
- **只对「服务」收费**：需要服务器成本的（云同步、免 Key 翻译代理）与高价值增值（AI 出新题、学习周报、多设备）；
- v1.0 **完全免费、无登录、无支付**：把审核复杂度降到最低，先验证留存（北极星指标：次日复习完成率）。

### 8.2 版本与付费节点

| 版本 | 内容 | 商业化 |
|---|---|---|
| v1.0（上架） | 复习 + 生词/词块 + 阅读 + 导入 + 分享收词 | 免费，无账号 |
| v1.x | 本地通知、小组件、听力通勤包、Android 版 | 仍免费（这些是留存工具） |
| v2.0 | **账号 + 云同步 + 翻译代理** | **Pro 订阅上线**（触发 SIWA/账号注销/IAP 合规，见 §6.2 注） |
| v2.x | AI 出新题、周报、家庭组 | Pro 增值 |

### 8.3 定价建议（v2.0 时验证，此处给锚点）

| 档 | 价格 | 内容 |
|---|---|---|
| 免费 | ¥0 | 本地全功能 + BYOK + 文件互导 |
| Pro 月付 | ¥12/月 | 云同步 + 翻译代理（公平使用额度）+ 周报 |
| Pro 年付 | ¥98/年（早鸟）→ ¥128/年 | 同上，折合 ¥8–10/月 |
| Pro 终身 | ¥328 一次性（可选） | 同上，限量早鸟 |

锚点参考：沉浸式翻译 Pro 约 ¥6.6–9.9/月（年付）、LingQ 约 $14/月、Readlang $5/月或 $85 终身、AnkiMobile $24.99 买断。我们定价中间偏上，靠「阅读→词块→产出复习」闭环差异化，不打价格战。

### 8.4 成本与抽成

- IAP 抽成：**App Store 小型企业计划 15%**（年净收入 <$100 万，需申请）；中国区用户可支付宝/微信支付，Apple 照抽；
- 翻译代理成本：按 token 进价核算，Pro 设「每月 X 万词」公平使用额度（参考沉浸式翻译的做法），超量降速不断供；
- Android（v1.x 后）：Google Play Billing 15%；国内若走官网 APK + 支付宝直充，无抽成但自担合规（届时需个体户/公司主体）；
- 收款主体：v1.0 阶段不涉及；v2.0 前决定（个人卡收款 vs 注册个体户，后者对公更稳，成本几百元/年）。

### 8.5 不做的事

- ❌ 免费层阉割复习量（背单词类常见做法，与「学会」的使命冲突）；
- ❌ 广告（与沉浸阅读场景互斥）；
- ❌ 卖用户数据（违背本地优先的产品承诺，也是隐私标签的法律红线）。

## 9. 质量与测试策略

- **单测**：`reader-core` 纯函数 vitest 全覆盖（现有 20+ 测试文件随迁保绿；`recallJudge` 新增完形/听写/trap/边界全套用例）；

- **UI 测试**：少量关键路径（复习评分落盘、查词收藏高亮）用 Testing Library；不做重型 E2E；
- **真机矩阵**：iPhone SE（4.7"）/ iPhone 15（6.1"）/ Pro Max（6.7"+）× iOS 16/17/18+，每里程碑至少一轮；
- **回归纪律**：桌面 Windows 端随 monorepo 重构跑全量 `npm run test`，schema 改动必须三端（Win/Mac 契约/iOS）同步评审。
