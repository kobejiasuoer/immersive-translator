## 二、反馈详情

### 1. 阅读室文件导入：需要 Word / PDF（可用性痛点）

**原话：**
> 阅读室的话现在不能直接上传文件，我看有一个可以上传txt的，但是现在word和pd【注：应为 PDF】比较多，粘贴文字有点麻烦

**解读：**
- 用户实际拿到的学习材料以 Word 和 PDF 为主，txt 不是真实世界的常见格式。
- 当前的替代路径（复制粘贴文本）被用户明确评价为「麻烦」，这是导入环节的摩擦，直接挡在核心阅读流程前面。

**建议：** 阅读/学习类产品的第一入口就是「把我的文件放进来」，docx 解析（前端 mammoth 或 Rust 侧 docx-rs）+ PDF 文本抽取优先级应排在本批反馈最前。

### 2. 口语陪练：本次反馈中最强烈的意愿

**原话：**
> （Judy X：你学英语现在需要啥）
> 生词本我还没用
> **我想要口语陪练呀**
> ……
> **111我想要这个**（引用自己上面那句「我想要口语陪练呀」）

**解读：**
- 在被直接问到「学英语需要什么」时，用户第一反应是口语陪练，并且随后又引用原话加「111」（+1）再次强调——是整段反馈里唯一被重复表达的诉求。
- 用户当前学英语的方式是「读 + GPT 整理笔记」，口语环节完全没有工具承接。

**建议：** 与 `docs/voice-roadmap.md` 中期规划（句子对话、语音 Agent 陪读）方向一致，本次反馈是对该路线图的直接用户验证。讯飞 ISE 发音评测已开通，可先以「跟读评测 → 对话陪练」的路径落地。

### 3. 录音直译（录音实时翻译）

**原话：**
> 可以搞一个那种录音直译😍😍
> 这个是不是很困难
> （Judy X：我问问他）

**解读：**
- 用户主动提出并配了表情、追问实现难度，兴趣明确；目前处于「待技术评估」状态。
- 指的大概率是「对着麦克风说话 → 实时转写 → 翻译」的同类功能（市面录音翻译笔/同传类 App 的形态）。

**建议：** 需要流式 ASR + 翻译链路，与阅读室现有 LLM 通道（`translation.rs`）和讯飞 WS 鉴权体系可复用，可先做技术 spike 评估成本。

### 4. 学词笔记：用户已经自己用 GPT 解决了

**原话：**
> 我用那个gpt建了一个skill，就是我 用他学英语的话，有些单词词组语法之类的让他帮我整理成markdown，方便我复习，就相当于他给我做了一份很好的笔记

**解读：**
- 强需求信号：用户不满足于被动接收，已经**自己动手搭建了 workaround**（GPT skill → 单词/词组/语法 → Markdown 复习笔记）。
- 她要的不是「背单词工具」，而是「把学习过程中遇到的东西自动整理成一份好笔记」。

**建议：** 产品已有生词数据和 OpenAI 兼容 LLM 通道，完全可内置「生词/词组/语法一键整理成 Markdown 复习笔记」，把用户的自建流程产品化，这可能是比截图翻译更具差异化的点。

### 5. 截图翻译：功能不突出（差异化质疑）

**原话：**
> 感觉可以看看有没有更独特一点的功能，比如说那个截图，现在虽然页面不完善，但是完善之后其实电脑截图再送到有道里拍照翻译也很快，豆包还有电脑自带的ai也有类似的功能
> 对我的意思就是这个功能不突出
> 很多软件有类似的功能
> （Judy X：截图的话，快捷键截图好像可以）

**解读：**
- 用户不是反馈截图难用（快捷键可用她也知道），而是质疑**这个功能不构成选择我们的理由**：有道拍照翻译、豆包、Windows 自带 AI 都有同类能力。
- 本质诉求是「更独特一点的功能」——担心产品同质化。

**建议：** 单点翻译功能难以对抗大厂全家桶；差异化更可能来自「阅读室 + 语音 + 学词笔记」的整合学习闭环，这与本批反馈的 1/2/4 条正好互相印证。

### 6. 生词本：还没被用上，且用户排斥「背单词」路线

**原话：**
> 生词本我还没用
> 我感觉英语不用太容易忘了
> 背单词的软件不要用🤣

**解读：**
- 生词本目前处于冷启动失败状态：用户还没用，且她对「背单词软件」这个品类本身有排斥情绪（🤣）。
- 结合第 4 条：同样是「复习学过的东西」，她拒绝的是背单词卡片的形态，接受的是「整理好的 Markdown 笔记」的形态。

**建议：** 生词本值得重新定位——从「背诵/复习卡片」转向「自动沉淀为复习笔记」，与第 4 条合并成同一个功能方向，而不是两个割裂的功能。

## 三、综合洞察

1. **用户画像与场景**：以「读英文材料 → 学词 → 复习 → 想练口语」为主线，材料来源是 Word/PDF，复习载体是 Markdown 笔记；不是背单词型用户。
2. **最痛的一刀在导入**：Word/PDF 不能直接传，是唯一一个「现在就挡着用户」的问题，建议最优先处理。
3. **语音方向被用户验证**：口语陪练（最强诉求）+ 录音直译，两条都指向语音，与 `voice-roadmap.md` 的中期/远期规划吻合，可据此调整优先级。
4. **生词本与学词笔记应合并考虑**：用户用行动投票——拒绝背单词软件、自建 GPT skill 生成 Markdown 笔记。「生词自动整理成复习笔记」是把她的自建流程产品化，也可能就是她要的「更独特一点的功能」。
5. **差异化判断**：截图翻译这类单点工具功能在大厂产品里已经普及，用户的价值感知低；独特性应押注在学习闭环的整合体验上。
