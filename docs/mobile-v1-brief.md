# 移动端原型 v1（iOS · P0）—— brief

> 交互原型：`prototypes/mobile-v1.html`（单文件、无依赖、四主题、`#demo=` 直达关键状态）
> 上游文档：`docs/mobile-app-research.md`（移动端调研与 P0 范围裁剪）
> 本文回答三件事：做了哪些屏、交互怎么定的、实现时注意什么。
> 截图存档：`prototypes/shots/mobile/`（9 张，含深色）。

---

## 0. 一句话

把桌面端闭环里「碎片时间」的部分装进 iPhone：**四个 Tab（今天 / 生词 / 书架 / 我的）+ 词典卡 + 系统分享收词 + 文件互导**。iPhone 优先，交互全部按 iOS 规范（底部 Tab Bar、大标题、底部抽屉、分段控件）；手机浏览器打开自动脱壳全屏（`<520px` 去 iPhone 壳）。

## 2. 关键交互决策（相对桌面端的差异）

1. **hover → tap**：正文中每个词可点；词块用虚线下划线、已收藏词用高亮（与桌面 `showVocabMarks` 同语义）。查词走底部词典卡，卡内直接收词（单词/词块二选一），收藏后**正文即时高亮、Tab 角标即时更新**。
2. **复数词形回落**：`lindens` 命中已收藏的 `linden`、`heatwaves` 命中 `heatwave`（原型内做了 -s 回落；实现时对应 `normalizeWordKey` 的归一化口径）。
3. **键盘 → 触控**：评分带四按钮 ≥58px 高，判分映射「建议」档描边可改选；`1–4` 快捷键保留（桌面演示用，真机无依赖）。完形输入框字号 17px 起，防 iOS 聚焦自动放大。
4. **复习队列与桌面同源**：同一批 8 张卡（取自 reading-room-recall 原型），智能路由（词块→完形、熟词→听写、新词→识别）不变——跨端一致是同步体验的一部分。
5. **阅读层是 push 语义**：盖住 Tab Bar，左上角返回；句级点按朗读 + 迷你播放条（倍速 0.85/1/1.25）；遮罩模式点中文逐段揭底。
6. **翻译可选**：书架内容默认「从电脑同步而来」（句子自带译文与词块标注），不填 API Key 即可完整使用——对应调研 §6.4 的零翻译起步。
7. **导语克制**：空态、报错、原型占位一律写清楚下一步动作（如词典卡未收录时说明「实际实现调用 readerDict」）。

## 3. 实现注意（给 Tauri 2 mobile spike 的输入）

- 数据模型零新增：文章/生词/词块/设置全部来自 `contracts/reading-room.schema.json` v1；导入合并规则（同词条按复习进度取最新）写进 v0 互导契约。
- 判分内核 `judge` / `wordDiff` / `normalize` 为纯函数，与规划的 `recallJudge.ts` 一致，可直接抽成跨端共享包（桌面 Windows/mac 与手机同源）。
- TTS：原型用 Web Speech 模拟；实现走系统 TTS（iOS `AVSpeechSynthesizer` / Android `TextToSpeech`），逐句连播按 `onend` 推进。
- 系统分享收词 = iOS Share Extension / Android 分享目标，原型只模拟了面板与后续流；Extension 本体无论选型都需要原生 Swift/Kotlin。
- 桌面快捷键（帮助面板里）在移动原型全部退化为触控，无键盘依赖。
