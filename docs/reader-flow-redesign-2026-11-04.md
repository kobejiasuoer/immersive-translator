# 阅读交互重设计 · 2026-11-04

状态：独立交互原型，尚未修改 React / Tauri 应用。本文以 `prototypes/reader-first-2026-11-04/` 的当前实现为准，取代上一版交互提案；已有业务设置与持久数据尚未迁移。

## 要解决的问题

上一版仍围绕句子和工具组织阅读：先选句，再找“查看第几句译文”，正文不断被操作入口切断。“译文阅读”偏离了阅读英文的目标；阅读过程中出现练习，也缺少明确动机。

这次把连续阅读作为默认状态。用户先读，遇到困难时主动选中需要帮助的内容，再决定是否查看解释。选择文字与请求帮助分开，保留普通选择、复制的用途。

## 当前交互

**正文是一篇连续的英文文章。** 默认不显示逐句按钮、句子编号、译文、解析空态或练习入口。顶部保留品牌、篇名、收藏与排版设置；文章呈现作者、英文标题和开篇节选标记。底部朗读器默认只显示播放与展开控制。

| 用户意图 | 动作 | 结果 | 返回阅读 |
| --- | --- | --- | --- |
| 查询一个词或表达 | 用原生文字选择选中词或短语，再点选区附近的“解释” | 打开紧凑解释卡，展示已收录的英文语境释义；有音标时显示音标，可听选中内容、收藏 | 关闭按钮、点卡片外部或 Escape 收起 |
| 理解完整句子 | 选中完整的一句话，再点“解释” | 显示原句和更易懂的英文改述 | 同上 |
| 理解句子结构 | 在解释卡内展开“句子结构” | 按原句片段呈现英文结构说明；默认收起 | 折叠结构或关闭卡片 |
| 只想选择或复制 | 选中文字后继续复制或其他原生操作 | 不自动打开解释；滚动、点击外部或 Escape 会收起选区旁入口 | 无需退出学习流程 |
| 留下有用的词句 | 在解释卡点“收藏”，或从顶部打开收藏列表 | 保存选文与释义；可取消收藏或在列表移除 | 关闭收藏列表 |
| 听原文 | 点底部播放按钮，按需展开朗读控制 | 系统英语语音逐句朗读；展开后可调整位置、上一句 / 下一句和语速 | 暂停或收起控制 |
| 调整阅读排版 | 打开 Aa | 调整字号与行距 | 关闭设置或点外部 |

单击单词不会自动查词，正文句子也不逐句进入 Tab 顺序。键盘可正常操作已经出现的按钮与解释卡；原型没有另设逐句 Enter 或按住键临时显示解释的手势。

桌面宽度下，解释使用 352px 宽、随内容增高的浮动卡，背景保持透明。位置优先利用正文左右的页边留白；没有足够留白时放在选区下方，接近底边则改放上方。卡片与视口保留 16px 边距，并根据可用空间限制高度；展开句子结构时重新计算位置，较长内容在卡片内部滚动，不挤压正文或改变页面滚动位置。宽度不超过 760px 时仍使用底部抽屉。

浮卡和抽屉均使用模态对话框维持键盘焦点，打开时锁住背景滚动，关闭后将焦点送回正文，并保留阅读位置。关闭后不会因保留着同一选区而立即重新出现“解释”入口，重新选择文字后才再次出现。卡片内容锁定当前主动选择的内容，不随朗读进度自动换句。

## 信息层级与朗读关系

帮助内容以英文为主：词语提供当前语境中的解释，整句提供简明英文改述；句子结构按需展开。界面操作文案使用中文，不提供中文译文阅读或全文双语切换。练习不放进这次阅读原型，未来进入练习的路径需在阅读之外单独设计。

选区旁的“解释”只在有效选择后出现，不占正文行、不预先列出每句操作。解释卡承担实际求助内容，单词标为“In this context”，短语标为“Expression”，整句标为“Sentence”；用户关闭后回到连续正文。

打开解释时会暂停正在进行的正文朗读。卡片内可以单独听选中内容；关闭卡片会停止尚未结束的选文音频。如果打开前正文正在朗读，则从当前句重新开始；如果此前处于暂停状态，则保持暂停。该原型没有恢复到一句话内部时间点的能力。

## 原型范围与限制

入口：`prototypes/reader-first-2026-11-04/index.html`，配套 `reader.css` 和 `reader.js`。无需安装依赖，释义数据不请求网络。示例为《快乐王子》开头节选，词义、英文改述和句子结构均为固定示例，不代表已经接入实时 AI、词典或翻译服务。

- 未收录的词或短语明确显示“示例尚未收录”，不会用整句说明冒充该选文的释义，并禁用收藏；仍可查看所属句子已收录的结构说明。
- 跨句选择会提示“选区过长”，建议缩短到词组或单句，不生成或冒充整段解释。原生选择与复制仍然可用；结构区域只展示已收录句子的拆解。
- 收藏使用当前浏览器的 `localStorage`，刷新后仍可保留，不同步到应用词库。浏览器拒绝写入时会提示，本次页面仍可使用收藏。
- “标记读完”仅演示当前页面的状态切换，字号、行距和朗读进度也尚未接入应用持久化。
- 朗读依赖浏览器的 Speech Synthesis 与可用英语语音；语音包、系统环境及浏览器支持会影响实际效果。

## 应用落地前

正式实现仍需沿用现有生词本、阅读进度和朗读链路。对旧 `contrastMode=zh`、遮罩偏好与历史 revealed 记录，应先确定兼容策略，不能直接删除持久字段。帮助对象与播放对象需保持独立，异步查询应取消过期请求并拦截旧响应。

还需在应用 WebView 中验证跨文本节点选区、复制手势、缩放后的入口位置、模态焦点恢复、滚动位置、触屏选区与朗读恢复。原型用于评审交互方向，不能替代正式业务集成与回归验证。

## 本轮实际验证

在浏览器中检查了 1280 × 720 桌面和 390 × 844 窄屏。已走通划词后主动解释、英文词义、结构展开、Escape / 关闭按钮返回、收藏与移除、字号调整、未知选文提示和禁用收藏。桌面卡片在视口内滚动，窄屏切换为底部抽屉；关闭后焦点回正文、页面滚动值保持，整篇正文不出现焦点黑框，也没有横向溢出。正文播放时打开解释会暂停，点选文发音后关闭会恢复正文播放状态；这验证了浏览器状态切换，未评估系统语音音质。最终控制台错误列表为空，`node --check` 通过。

本轮未验证触屏长按选区、真实 Tauri WebView、所有长选区和缩放组合。原型对视口内空间不足的长选区设有可滚卡片回退，仍需在正式应用中回归。
